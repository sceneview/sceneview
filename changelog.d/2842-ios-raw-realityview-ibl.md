- **iOS demo: two PBR demos now go through the wrapper's IBL path ([#2842](https://github.com/sceneview/sceneview/issues/2842)).** `TextureStreamingDemo` and `OcclusionMaterialDemo` built their PBR entities on a raw `RealityView`, so the `.environment(.studio)` modifier — defined on `SceneViewSwift.SceneView`, which applies IBL via `ImageBasedLightComponent` — could not reach them. `TextureStreamingDemo`'s sphere lived in a `RealityView` overlay stacked on top of its own empty `SceneView`; `OcclusionMaterialDemo` used no `SceneView` at all. Both now build their entities inside the wrapper's content closure and carry `.environment(.studio)`, the same preset `ModelViewerDemo` / `MaterialsDemo` use (#2114). Because that closure runs once (it is RealityView's `make:`), the reactive material swaps — the preset picker and the occluder toggle — now mutate a stashed entity reference from `onChange`, the pattern already used by `MultiModelDemo` / `MovableLightDemo`, instead of a `RealityView` `update:` closure. Follow-up to the L1.1 IBL sweep (#2805), which deliberately left these two aside rather than shipping an `.environment()` call that would silently do nothing. This changes which lighting path the demos take; it is not a verified rendering result — see the PR description for what was and was not checked.

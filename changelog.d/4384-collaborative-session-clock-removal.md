- **`CollaborativeSession`: two peers writing the same node key now end on the same node, a shared node can be removed, and `broadcastLocalPose` is rate-limited ([#4384](https://github.com/sceneview/sceneview/issues/4384)).** Each `placeNode` carries a per-key counter (`NodeState.logicalClock`, a trailing `clock` field on the `node` line), set above every counter the writer has seen for that key and never below its wall clock; equal counters are settled by the greater peer id, so the result no longer depends on the order the lines arrive in. New `CollaborativeSession.removeNode(nodeKey)` removes a node on every peer (`remove` line, `CollaborativeMessage.NodeRemoval`): a placement written before the removal and delivered after it does not bring the node back, a later `placeNode` places it again. **Behaviour change:** `broadcastLocalPose(Pose)` now honours `poseRateHz` like `onFrame` — the first pose is sent at once, then one per interval, and the newest pose held back is sent when the interval ends, so the pose a device stops on is no longer lost; a caller that relied on every pose going out passes `poseRateHz = 0`. Peers up to 4.53.0 interoperate: they ignore the counter and drop `remove` lines, and their own writes are applied in arrival order. Binary change: `NodeState` gains a seventh constructor parameter (the six-argument constructor is kept; `copy` and `componentN` change).

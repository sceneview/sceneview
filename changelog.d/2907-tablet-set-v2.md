- Play Store tablet screenshots are back in step with the phone set. #2855 moved the Android showcase to **set v2** (`model-viewer · dynamic-sky · multi-model`) but re-shot the **phone** class only, so the 7"/10" slots kept uploading the retired pre-v2 demos on every `vX.Y.0` tag — `materials`, whose HDRI *and* model change per launch so the frame is not reproducible (#2874), `geometry`, whose primitives clip a portrait frame (#2873), and `double-pendulum`, a tiny linkage in a mostly-black frame. Both tablet classes are re-captured from set v2 on their own AVDs (a 10" `pixel_tablet` and a 7" `Nexus 7`, never the same device twice), against a freshly built app rather than a stale one — the previous tablet PNGs had been shot from a build two minor versions behind, which is how they missed the demo bottom-overlay fix (#2780).
- Tablets ship the first **two** v2 frames, not three: `multi-model`'s fixed camera angle lands on a wooden support post at a tablet's wider aspect ratio (~0.63 w/h vs the phone's ~0.47), showing none of the foliage the slot exists for. It is not a load/settle defect — the frame renders fully — and the `camera_distance` lever cannot correct it (probed at 2.5 / 3.5 / 4.5 m on both tablet AVDs: essentially the same frame, because distance moves the camera along an angle it cannot change). The variance guard passes the bad frame, so the capture script now drops `multi-model` from tablet runs, with the measurement recorded next to the default so it is not re-added on the strength of a green run. The demo-side framing fix is tracked in #2913 (#2907).
- Corrected four store-doc surfaces that had drifted into claims the repo contradicts: `PLAY_STORE_SETUP.md` still advertised five phone screenshots and a cross-store "same five demos" parity; the Play graphics README still listed the retired pre-v2 five as the shipped set and carried framing follow-ups for demos no longer in it; the capture script's own usage example still offered the retired ids as the `--demos` sample; and the App Store screenshots README claimed parity with Android while its committed images are the pre-v2 five, deferred on scene-side RealityKit fixes (#2896). The two stores are now documented as deliberately out of sync rather than described as identical (#2907).

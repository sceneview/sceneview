- **The AI-facing surfaces stopped telling assistants the wrong thing ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** An audit of every surface an AI reads found four independent falsehoods, each on a file whose whole job is to be machine-truth. `.cursorrules`, `.windsurfrules` and `.github/copilot-instructions.md` all handed out `io.github.sceneview:sceneview:4.0.0` — 30 minors behind `VERSION_NAME` — because `sync-versions.sh` swept those files for their SwiftPM snippet only, and `.windsurfrules` for nothing at all; 115 version checks passed while the SDK's AI-first surfaces were the stale ones. `.cursorrules` also still pinned SPM to the archived `sceneview-swift` mirror, invisible to `check-sceneview-swift-urls.sh` because every pathspec it scans is an extension glob and the file has no extension. `docs/docs/ai-development.md` documented four MCP tools of which three (`get_api_reference`, `get_sample_code`, `get_threading_rules`) have never existed, and described `llms.txt` as 500 lines when it is 7,619. The homepage's JSON-LD, its stat tile and the README advertised 28 MCP tools against a real 31.
- **Both gates that missed those now cover them.** `sync-versions.sh` gained a Maven-coordinate sweep over the three rules files (118 checks, verified to fail on a reintroduced `4.0.0`), and `check-sceneview-swift-urls.sh` now scans extensionless agent rules files, with `.claude/plans/*.md` free to name the retired mirror in prose but still refused a live pin. Three self-test cases pin the new behaviour and each was mutation-checked against the fix being removed (15 passing).
- **`AGENTS.md` is now the single agent rules file, and its Kotlin is compile-checked ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** The repo carried three hand-maintained rules files — `.cursorrules`, `.windsurfrules`, `.github/copilot-instructions.md` — that had drifted apart from each other and from the SDK. They are now thin pointers to a single [`AGENTS.md`](https://github.com/sceneview/sceneview/blob/main/AGENTS.md), the cross-vendor standard read natively by Codex, Cursor, Copilot, Gemini CLI, Aider, Windsurf and Zed, and it is wired into the existing snippet harness (`tools/extract-doc-snippets.js`, `snippets-check.yml`) so its Kotlin compiles in CI alongside `llms.txt` — the rules an assistant reads are now the rules that build. Writing it surfaced two falsehoods the first pass had missed: `copilot-instructions.md` listed four node types that have never existed (`GeospatialNode`, `DepthNode`, `InstantPlacementNode`, `ArrowNode`), and the `.cursorrules` Swift example called a `SceneView(environment:)` initializer and a `ModelNode(named:)` that `SceneViewSwift` does not have — the real API is the `.environment()` modifier and `try await ModelNode.load(_:)`.
- **The MCP client list now matches what we actually support.** Install paths for **OpenAI Codex** (`codex mcp add`, `~/.codex/config.toml`) and **Gemini** (Antigravity CLI, and the Streamable HTTP endpoint for Gemini Enterprise) were absent from every public surface and are now documented in the README, `mcp/README.md`, `docs/docs/ai-development.md`, `docs/docs/ai-context.md` and the homepage install tab. Sweeping for the stale "28 tools" claim found five more sites than the audit predicted — the homepage stat tile, feature card, comparison table and JSON-LD, plus `docs.html` and `claude-3d.html` — and `playground.html` turned out to ship a copy-to-clipboard prompt naming five MCP tools that do not exist (`create_scene`, `add_model`, `configure_camera`, `set_environment`, `add_ar_plane_detection`), handed straight to the reader's assistant. All now derive from the real 31.
- **A gate now refuses prose that invents MCP tools or mis-states their count ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** Every falsehood the audit found was one shape — a fact about the MCP server typed by hand into a surface no gate could see — so the fix is a gate that reads the real registry instead of trusting the prose. `tools/check-mcp-tool-claims.js` parses tool names from `mcp/src/tools/definitions.ts`, the gateway widget tools and the five vertical packages (67 known tools), then scans 109 public prose files for two things: a verb-prefixed snake_case token in inline backticks that is in no registry, and an "N tools" claim whose N matches no real surface. It found two more stale sites on its first run that the manual sweep had missed — `gpt/system-prompt.md` ("28 AI tools", and an `sceneview-mcp` version pinned at 4.0.12 against a published 4.0.16) and `pro/gpt-store/gpt-instructions.md` ("28 tools"). Fenced code blocks are skipped, `CHANGELOG.md` and its docs-site mirror are excluded because a release note naming a since-removed tool is history rather than a false claim, and a registry that fails to build exits 2 rather than reading as an empty registry that would rubber-stamp every claim. Wired into `pre-push-check.sh` (now 22 steps) and the CI repo-hygiene job, with an eight-case self-test pinning both directions — one of whose cases was itself found vacuous by mutation testing and rewritten before it could ship.
- **The same gate now derives the sample count, which was wrong in seven places.** `mcp/src/samples.ts` defines **38** scenarios; "33 compilable samples" stood in `README.md`, the homepage feature card, `AGENTS.md`, `docs/docs/ai-development.md` and three lines of `mcp/README.md`. Two of those were written during this very cleanup, by copying the number out of a README instead of deriving it — which is the argument for the gate, made against its own author. `mcp/README.md` also disagreed with itself on its test count: the badge said 1898 and the CONTRIBUTING line said "1898+" while the body said 1,965. Measured this run with `npx vitest run`: **83 files, 1965 tests**, so the badge and the contributing line were the stale halves and now match. The self-test grew to 12 cases; every one was mutation-verified, and two were found vacuous that way and rewritten before shipping.
- **The tool-claim gate now derives the tier split, and refuses rather than narrowing itself in silence ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** `tools/check-mcp-tool-claims.js` compared every "N tools" claim against the stdio count, the mounted total and the per-package counts — but not the **free/Pro split**, which is legitimate to advertise and derivable from neither. Measured: the stdio package defines 31 tools of which three are Pro (`render_3d_preview`, `create_3d_artifact`, `generate_scene`), so its free surface is 28; adding the gateway-only-but-free `view_3d_model` gives 29 free against 38 Pro, totalling the 67 mounted. `mcp/mcpize.yaml` advertises "28 free tools" and is **right** — the gate would have rejected it and pushed a reader to break a true claim, which is worse than missing a false one. The split is now parsed from `mcp/src/tiers.ts` and folded into the accepted set. The first attempt at that parse assumed the arrays close with `];` when they close with `] as const;`, matched nothing, and dropped the counts with **no error at all** — so the gate now exits 2 on an unparseable tier map, the same contract it already had for the registry and the sample count. Self-test 12 → 14 cases; one of the two new ones was found vacuous under mutation (its fixture reached the assertion through `free - 1` rather than the Pro count) and was rewritten with a distinct Pro count before shipping.
- **Seven false tool counts on the live commercial gateway, and the gate that could not see them ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** `mcp-gateway/src/dashboard/` — the pricing page a subscriber reads and the docs page the gateway serves — sat outside every pathspec of `check-mcp-tool-claims.js`, exactly the way `.cursorrules` sat outside the archived-mirror gate. The gate scans the dashboard (115 prose files, up from 109), its count pattern now allows a qualifier between the number and the noun — "27 **free** tools" walked past the first version while "27 tools" was caught, which reads as coverage without being it — and the vertical aggregate and package count join the derived set so a true claim cannot be rejected.
- **`docs/docs/llms-full.txt` no longer calls itself the complete API reference.** Its first line read "SceneView — Complete API Reference for AI Systems" on a **292-line** file, while the actual complete reference, `llms.txt`, is 7,619 lines. Any agent following the `llms.txt` convention fetched 4% of the API believing it had all of it — a thesis-level defect for an SDK whose stated test is whether an AI can read this and emit working code. The header now says which file is which and points at the full one. The names stay inverted and the URLs stay put: they are load-bearing for external consumers, and renaming them was never the cheap fix — the header was.

- **The Gemini Enterprise route is now labelled untested instead of stated as fact ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** Four public surfaces — `README.md`, `mcp/README.md`, `docs/docs/ai-development.md` and `docs/docs/ai-context.md` — asserted that Gemini Enterprise accepts a Streamable HTTP MCP URL. That came from a secondary source; a verification pass found Google's own documentation URL 404s after redirect, so the claim is reported but unconfirmed. - **Two repo-hygiene self-tests had been failing on every mawk host and every host without `xxd` ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** `pre-push-check.sh` reported "2 of 41 gate self-test(s) failed" on a clean tree, which is the worst possible state for a gate: red on `main`, so a reader learns to skim past it. `test-ci-gate-observations.sh` extracted `ADVISORY_CHECKS` from `ci-gate.yml` with an awk regex using a POSIX bracket interval (`{10,}`) — Ubuntu's `/usr/bin/awk` is **mawk**, which implements no bracket intervals and offers no flag to enable them (`-W re-interval` is a vacuous option there), so the pattern matched nothing, the extractor exited on its first value line, and the suite hard-failed with "could not extract ADVISORY_CHECKS". Ten literal spaces express the same block-scalar indent and work under mawk, gawk and BSD awk; the extractor now yields the real list (`Coverage`, `Agent review`) and still tracks a change to it. `test-store-preflight.sh` hard-failed with `xxd: command not found` on hosts lacking `xxd` — a missing tool is not a regressed ES256 signer, and `xxd` remains a declared, checked dependency of `store-preflight.sh` that ships on ubuntu-latest — so that case now skips honestly, the same shape as the neighbouring shellcheck assertion. Both suites pass; the hygiene gate is 41/41 for the first time in this branch's history.

Self-test 14 → 19 cases. On the prose side, `gpt/system-prompt.md` still handed out `4.3.1` on three lines while the SwiftPM clause between them read `4.30.0` — the same "listed for one coordinate is not covered for the other" shape as `pro/gpt-store/gpt-instructions.md` one file over, so both now sit in the Maven sweep and the two non-Maven version lines got a check of their own (121 checks). `landing.tsx` advertised 27 free / 27 Pro / 4 packages against 29 / 38 / 5, and the pricing FAQ credited all 31 stdio tools to the free tier when 28 of them are free; `pre-push-check.sh` now runs the gate's self-test beside the gate and finds a nvm-installed `node` instead of reporting `NOT_COVERED` on a host that runs it fine; and `gradle-run.sh`'s foreign-checkout detector stopped treating `=`, `:` and `,` as path interior, which had narrowed it in the unsafe direction while fixing a false red.

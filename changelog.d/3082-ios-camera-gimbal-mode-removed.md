- **iOS/macOS: `CameraControlMode.gimbal` is gone — RealityKit never had a gimbal camera mode ([#3082](https://github.com/sceneview/sceneview/issues/3082)).** `RealityFoundation.CameraControls` is a struct exposing exactly five values — `.none`, `.tilt`, `.pan`, `.orbit`, `.dolly` — and no SDK has ever shipped a `.gimbal`; the interfaces bundled with Xcode 26.3 (iOS 26.2, macOS 26.2, visionOS 26.2) contain zero occurrences of the word. SceneView nonetheless exposed a public `.gimbal` case documented as *"Equivalent to `RealityKit.CameraControls.gimbal`"*, and every platform branch fell through to the hand-rolled orbit gesture path — so `.cameraControls(.gimbal)` was a silent alias for `.orbit` that named an API which does not exist. Use `.orbit` (or Apple's `.tilt` / `.dolly`) instead. The iOS demo's native-mode picker never offered the mode, so no demo behaviour changes.

<!-- category: Docs -->

- **The AI-first doc surfaces no longer promise a camera mode the SDK cannot honour ([#3082](https://github.com/sceneview/sceneview/issues/3082)).** `llms.txt`, the regenerated `gpt/knowledge-api.md`, `docs/docs/cheatsheet-ios.md` and the `sceneview-ios` agent skill + cheatsheet all advertised `.gimbal` as a native Apple mode, which is the worst class of documentation debt for this repo: an AI that reads it emits code that does not compile. The `CameraControlMode` block now states outright that RealityKit's `CameraControls` has no `.gimbal`, and that `.pan` / `.orbit` are the two Apple modes SceneView deliberately implements itself for Android parity. A `SceneView.swift` `TODO(#1049 Phase 3)` that gated the mode on "all CI runners use Xcode 16.2+" went with it — a condition ten Xcode majors in the past that could never have unblocked anything.

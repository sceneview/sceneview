<!-- breaking -->
- **Geometry updates rebuild buffers when vertex counts, per-submesh index counts or attribute layouts change ([#4344](https://github.com/sceneview/sceneview/issues/4344)).** `Geometry.update` and every `updateGeometry` used to write the new lists into buffers sized once at construction, so a sphere going from 8 to 64 slices, a path gaining a point or a shape gaining a colour overran them. Same-size edits still rewrite the existing buffers in place, and now rebind the node once instead of twice. A geometry shared by several nodes re-points every one of them (primitive ranges, bounds and collider included); the replaced buffers are destroyed right after, and a geometry is destroyed as soon as its last node is — neither waits for a rendered frame. Shape updates now forward normal, UV scale and colour.
- **A rebuild obeys the one-upload-in-flight rule of [#4365](https://github.com/sceneview/sceneview/issues/4365).** A geometry that changes size on every update while Filament consumes nothing keeps one upload in flight and only the latest state, like a same-size edit. This amends that entry's "`boundingBox` still changes immediately": it does for an update that fits the buffers, and for a rebuild issued during the call. A rebuild that has to wait for the previous upload leaves `vertexBuffer`, `indexBuffer`, `primitivesOffsets` and `boundingBox` describing the buffers still on screen, and switches the four together with the nodes when it goes out; `vertices` and `primitivesIndices` always change during the call. `setVertices` and `setPrimitivesIndices` are now `update` with one argument, so they accept any count too.
- **An index update uploads the index values.** Since the #4365 change, `Geometry.update` / `setPrimitivesIndices` with new indices of the same count wrote `0, 1, 2, …` into the index buffer instead of the indices they were given, so a geometry re-triangulated in place drew the wrong triangles.
- **Breaking — `GeometryNode` constructor:** the primary constructor adds `mergePrimitives: Boolean` after `builderApply`. Dynamic layouts support the geometry's natural submeshes or one merged primitive only.
- **Breaking — a node owns the geometry it is bound to:** `RenderableNode.setGeometry(other)` now destroys the geometry it replaces once no other node references it; binding that geometry again throws `IllegalStateException`. Build a new `Geometry`, or keep a second node bound to the one you want to return to. `GeometryNode.setGeometry` only accepts its own geometry object.
- **Breaking — custom primitive offsets are rejected:** passing `GeometryNode` `primitivesOffsets` that are neither the geometry's own nor one range covering every index throws `IllegalArgumentException`, since such a layout cannot follow a topology change.
- **Breaking — glTF renderables can be rebuilt:** `setGeometry` on a `ModelNode` renderable with a geometry whose primitive count differs from the glTF mesh's now rebuilds the Filament renderable instead of leaving the extra primitives undrawn. New primitives inherit the last material. A rebuild carries over what Filament lets it read back — priority, channel, culling, fog, shadow flags, light channels, instance count, materials, blend orders — plus the layer mask set through `setLayerMask` and whatever `builderApply` configures; a skinning buffer, bone matrices or an `InstanceBuffer` set any other way are not carried over (re-apply them after the update), and changing the primitive count of a morphed renderable is rejected.
- **Breaking — degenerate geometry throws instead of aborting:** building or updating a `Geometry` with no vertex, or a `Path` with fewer than 2 points (`Path.getVertices` included), throws `IllegalArgumentException`.
- `Geometry.vertexBuffer` and `indexBuffer` are now properties with private setters: read them again after a topology change. Lending them to a `MeshNode` stays supported as long as every update keeps the vertex count, the per-submesh index counts and the attribute layout — the buffers are then never replaced. A lent `MeshNode` is not rebound by a rebuild: use a `GeometryNode` when the topology can change, and destroy the `MeshNode` before, or in the same pass as, `engine.safeDestroyGeometry(geometry)`.

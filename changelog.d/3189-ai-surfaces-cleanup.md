- **The AI-facing surfaces stopped telling assistants the wrong thing ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** An audit of every surface an AI reads found four independent falsehoods, each on a file whose whole job is to be machine-truth. `.cursorrules`, `.windsurfrules` and `.github/copilot-instructions.md` all handed out `io.github.sceneview:sceneview:4.0.0` — 30 minors behind `VERSION_NAME` — because `sync-versions.sh` swept those files for their SwiftPM snippet only, and `.windsurfrules` for nothing at all; 115 version checks passed while the SDK's AI-first surfaces were the stale ones. `.cursorrules` also still pinned SPM to the archived `sceneview-swift` mirror, invisible to `check-sceneview-swift-urls.sh` because every pathspec it scans is an extension glob and the file has no extension. `docs/docs/ai-development.md` documented four MCP tools of which three (`get_api_reference`, `get_sample_code`, `get_threading_rules`) have never existed, and described `llms.txt` as 500 lines when it is 7,619. The homepage's JSON-LD, its stat tile and the README advertised 28 MCP tools against a real 31.
- **Both gates that missed those now cover them.** `sync-versions.sh` gained a Maven-coordinate sweep over the three rules files (118 checks, verified to fail on a reintroduced `4.0.0`), and `check-sceneview-swift-urls.sh` now scans extensionless agent rules files, with `.claude/plans/*.md` free to name the retired mirror in prose but still refused a live pin. Three self-test cases pin the new behaviour and each was mutation-checked against the fix being removed (15 passing).

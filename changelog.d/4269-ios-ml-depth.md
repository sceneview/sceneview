- **SceneViewSwift**: monocular ML depth for iPhones without LiDAR. `ARSceneView(...).depthSource(.ml(estimator))` (or `.auto(ml:)`, LiDAR first) turns the camera image into a metric `ARDepthFrame` with `source == .ml` at about 10 Hz off the main thread: the relative depth is scaled to metres with a robust fit `1/z = s·d + t` against ARKit's feature points and plane raycasts (consensus seed, Huber IRLS, outlier rejection), smoothed over time, held for a few frames when anchors drop out, run at half rate at a serious thermal state and paused at a critical one (as Android: only SEVERE pauses), and paused while tracking is lost. `.onDepthFrame` and `.onDepthSourceState` report frames and status; names match Android (`DepthSource.native/.ml/.auto`, `ARDepthFrame.source`), and the waiting state carries its anchor count like `MlDepthState.WaitingForAnchors(anchors)`.
- **SceneViewDepthML** (new, separate product): `DepthAnythingV2Estimator` runs Depth Anything V2 **Small** (Apache-2.0, Apple's Core ML conversion, 8-bit weights) on the Neural Engine. The package bundles no model: `DepthModelStore` downloads it once from a pinned revision with SHA-256 checks (25.4 MB, against 27.7 MB for Android's int8 model), compiles it and swaps it into a cache keyed by name and revision, and purges and re-fetches it once if a cached model no longer loads; it also takes an app bundle resource or an On-Demand Resources tag. Base and Large are not supported (non-commercial licence).
- **iOS demo**: new **Depth Visualization** screen — false-colour depth over the camera with a Camera-to-Depth blend, a LiDAR / ML source pill and an ML card (download, preparing, waiting for surfaces, cost per estimate, holding, thermal pause, failure), mirroring Android.

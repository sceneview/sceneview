- **Disposing a scene no longer blocks the main thread on the GPU backend ([#4828](https://github.com/sceneview/sceneview/pull/4828)).** Deferred releases (`destroyRenderer`, the engine, a cancelled async model load) waited for a fence created when they were deferred, then ran a Filament release that waits for everything queued since: on a shared engine, the next screen's shader compilations, an ANR from the main looper. They now wait until the backend has recently caught up with its queue, however slowly the main thread polls, and fall back to the previous behaviour after 5 s at most, the engine's own destroy included. The engine is also built with `engine.frame_info.disable_gpu_complete_metric`, so `destroyRenderer` no longer joins a thread parked in an unbounded GPU fence wait, and `VideoNode.destroy()` releases its external texture once the backend is idle instead of draining it synchronously.

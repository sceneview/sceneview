- perf(sceneview): cut per-frame and per-reparent Filament JNI on Android `Node` transform/parent hot paths ([#2328](https://github.com/sceneview/sceneview/issues/2328)). `Node.transform` now reads from a local-matrix cache instead of JNI-ing `TransformManager.getTransform` on every read (the smooth-animation tick reads it once per frame); the cache stores the exact matrix last pushed, so non-TRS matrices still round-trip bit-for-bit. `parentEntity`/`parentInstance` now resolve the parent from a cached entity, removing the redundant double `getParent`/`getInstance` JNI on each reparent and on every parent read. `Node.rotation`'s per-read `Float3` is documented as deliberately un-cached — it is not a per-frame path (the render/animation loop reads `quaternion`). All changes are behaviour-preserving.

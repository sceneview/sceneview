- **Scene Semantics classes are read in ARCore's own order ([#4036](https://github.com/sceneview/sceneview/issues/4036)).** ARCore numbers `UNLABELED` first (`0`), then `SKY` (`1`) to `WATER` (`11`); SceneView read the semantic image as if `SKY` came first, so three things were one class off. `ARCameraStream.isPersonOcclusionEnabled` built its mask from `VEHICLE` pixels instead of `PERSON`, hiding virtual content behind cars and not behind people. The `semantics_overlay` material (`MaterialLoader.createSemanticsOverlayInstance`) gave each class the next one's colour, tinted unclassified pixels sky blue and left water transparent. And the demo app's Scene Semantics overlay did the same against its own legend: a wall ARCore called a building was painted in the legend's "Tree" green, a chair it called an object in its "Vehicle" blue, and "Nothing classified yet" never showed. The `Frame.semanticImage()` documentation now gives the order and a decode line that compiles (`SemanticLabel.values()[byte.toInt() and 0xFF]`; `SemanticLabel.forNumber` is not public).

- **The Kotlin/JS test browser is now configured to survive a CI runner, and to say what happened when it does not ([#3192](https://github.com/sceneview/sceneview/issues/3192)).** The blocking `Build web targets` leg died five times on #3189 with `Test running process exited unexpectedly` — zero test results, and no Karma or Chrome output anywhere in a ~4500-line job log. Gradle reported the `jsBrowserTest` inputs byte-identical to `main`, so the branch content was ruled out mechanically; the cause was never observed because nothing captured it. `sceneview-core` was a bare `browser()`: no `--no-sandbox`, no `--disable-dev-shm-usage`, no activity timeout, no console capture. Both Kotlin/JS modules now carry a byte-identical `karma.config.d/browser-hardening.js` with a hardened launcher, timeouts sized for a loaded shared runner, and browser-console capture that CI uploads on failure. `retryLimit` re-attempts browser *capture* only — the suite itself is never retried, since a retried suite would hide the flake this change exists to make visible. `.claude/scripts/check-karma-hardening.sh` fails the quality gate if a module ships without the config, if the two copies drift, or if the hardened launcher loses a flag; it exits 2 rather than 0 when it discovers no modules at all.
- **`karma.config.d/` is now part of the Kotlin/JS test task's identity, so a change to it actually re-runs the tests ([#3192](https://github.com/sceneview/sceneview/issues/3192)).** Those files are appended verbatim into the `karma.conf.js` the task generates, so they change what the run does — but Gradle tracked neither of them as an input. Measured: pointing `config.browsers` at a launcher that does not exist and re-running gave `BUILD SUCCESSFUL` with `:sceneview-core:jsBrowserTest UP-TO-DATE`, against a stale generated config, while the identical break under `--rerun-tasks` failed in 4 s with `Cannot load browser … it is not registered!`. Both modules now declare `inputs.dir("karma.config.d")`, and the same break re-runs and fails without `--rerun-tasks`. The blast radius is local, not CI — `jsBrowserTest` is not cacheable and a fresh CI checkout has no up-to-date state to reuse — but local Gradle is the only place a Karma config is ever verified, so this silently made the previous entry's hardening unverifiable on the machine that had to verify it. The gate asserts the declaration, so the config cannot drop out of the input graph again without failing the build.

- **`VideoMaterial.destroy()` no longer crashes the next frame ([#4859](https://github.com/sceneview/sceneview/pull/4859)).** It freed its video texture and stream but left its material instance alive, still bound to the freed texture; Filament commits every material instance of the engine each frame, so the next frame aborted with `Invalid texture still bound to MaterialInstance`. The instance is now destroyed first, and the texture and stream once the backend has executed that destroy, as `VideoNode` already does. Remove `instance` from any renderable that uses it before calling `destroy()`.

- **Animated geometry no longer aborts the app when frames are not being presented ([#4365](https://github.com/sceneview/sceneview/issues/4365)).** `Geometry.update` (and `setVertices` / `setPrimitivesIndices`, so every `TubeNode`, `PathNode`, `LineNode`, `ShapeNode`… updated per frame) handed Filament a fresh set of buffers on every call. Filament pins each one with JNI global references until its backend thread has consumed the upload, so a geometry animated from Compose's frame clock while the view presented nothing — before the first frame, or behind a busy GPU — piled references up until ART's 51 200-entry table overflowed (`JNI ERROR (app bug): global reference table overflow`). A geometry now keeps one upload in flight and only the latest state set while it waits; that state is uploaded as soon as Filament releases the previous one, and render-on-demand views — `ARSceneView` included — are woken for it. `vertices`, `primitivesIndices` and `boundingBox` still change immediately, and the lists are copied during the call, so a reused `MutableList` cannot alter an upload that is still waiting. One visible difference: two updates made before a frame is drawn used to land in that same frame; now the frame may show the first and the next frame the latest. `setVertices` followed by `setPrimitivesIndices` are two uploads, so a frame can show new vertices on old indices — change both with one `update(engine, vertices, primitivesIndices)`, which uploads them together.
- **Demo app: Lines & Paths no longer closes on a slow start.** Opening it while the device was busy could end the app before the route appeared.

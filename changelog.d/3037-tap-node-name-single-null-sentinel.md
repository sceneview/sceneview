- **`TapEvent.nodeName` is now typed `string | null` — no longer optional** (React Native). It was `string | null | undefined`, because `ARSceneView` on iOS built its payload from `onTapOnPlane` and left the key out entirely: `nodeName === null` meant "the tap hit no model" on three dispatch paths and `undefined` meant the same thing on the fourth, so every consumer needed a two-sentinel guard to be correct. The iOS AR payload now writes `"nodeName": NSNull()`, matching Android's `putNull` and the iOS 3D view, and all four paths — Android `SceneView`/`ARSceneView` (one shared `TapEvent.getEventData`), iOS `SceneView`, iOS `ARSceneView` — always emit the key. **One `nodeName == null` check is now correct everywhere.** Dropping `undefined` from the type is source-breaking under `strictNullChecks` for code that narrowed with `=== undefined` or assigned `nodeName` into a `string | undefined` binding; `== null`, truthy checks and `?.` are unaffected.
- **No Flutter change — decided, not overlooked.** The Dart callback is `void Function(String nodeName)` and its contract is genuinely different, not the same asymmetry: it is only ever invoked *because* something was hit (Android attaches `onTouch` per model; iOS uses `onEntityTapped`), so there is no "missed everything" dispatch to carry a sentinel. `''` already covers the one reachable near-miss — an iOS hit on an entity outside a bridge-loaded model — uniformly. On `ARSceneView` under iOS the callback never fires at all, because `SceneViewSwift.ARSceneView` exposes no entity hit-test hook ([#2051](https://github.com/sceneview/sceneview/issues/2051)); that is a missing capability, not a sentinel to align, and widening `String` to `String?` on a published pub.dev API would be source-breaking for Flutter consumers in exchange for a state the bridge cannot produce.

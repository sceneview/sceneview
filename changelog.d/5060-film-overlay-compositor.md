<!-- category: Fixed -->
- **`SceneRecorder` videos with an overlay record twice as many frames ([#5060](https://github.com/sceneview/sceneview/pull/5060)).** The overlay compositor waited on the CPU for each mirrored frame's GPU fence while holding a lock that Filament's render thread also needs. It now composites the scene and the overlay in one OpenGL ES pass, and the GPU does the waiting. On a Pixel 4a, a 1080p recording goes from about 10 fps to 20 fps, and the preview frame rate does not change. The ImageReader compositor stays as a fallback for devices where EGL cannot be set up on the encoder surface. An overlay that throws now costs only the overlay: the frame is still recorded with the scene alone, and the failure is logged once.

<!-- category: Changed -->
- **Video overlays draw on a software canvas ([#5060](https://github.com/sceneview/sceneview/pull/5060)).** On API 29+, `CaptureOverlay.draw` now gets a software `Canvas` for video frames, as it already did for photos. A video overlay can no longer draw `Bitmap.Config.HARDWARE` bitmaps (decode logos with a software allocator) or call `drawRenderNode`. If it does, the overlay is left out of those frames and the scene is still recorded.

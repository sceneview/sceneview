- **Android: the render loop no longer walks the whole node tree on every vsync to learn whether a node is active ([#3724](https://github.com/sceneview/sceneview/issues/3724)).** Under `FrameRatePolicy.OnDemand`, `SceneView` and `ARSceneView` asked every root for `isFrameActive` on each tick, and that getter recurses into every child: a second full traversal per frame, complete exactly when the scene is idle. Each scene now keeps the set of nodes that can answer yes — a node holding an `onFrame` callback, a smooth-transform target or an activity provider, and every `ModelNode`, `BillboardNode`, `TextNode`, `VideoNode`, `ViewNode` and `SplatNode` — and asks only those. A plain node costs nothing, however many the scene holds. No answer is cached, so a term nobody reports (a player that starts, a physics body that wakes) is still seen on the next tick. A node type that overrides `isFrameActive` itself keeps working unchanged: it is asked in full on every tick, as before.

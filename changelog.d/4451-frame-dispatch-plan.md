- **Android: a rendered frame no longer calls `onFrame` on every node of the scene ([#4451](https://github.com/sceneview/sceneview/issues/4451)).** `SceneView` and `ARSceneView` handed each frame to every root, and `Node.onFrame` recurses into every child: one virtual call, one time-step computation and one child iteration per node and per frame, for a tree where most nodes have nothing to do. Each scene now walks its tree once, keeps the calls that walk made — a smooth transform to advance, an `onFrame` callback or a library hook to invoke — in the order it made them, and replays that list until the tree or one of those slots changes. Measured on the Debug Overlay stress scene (1,064 nodes, debug build, emulator): 0.78 ms per frame before, 0.006 ms after. A node type that overrides `onFrame` — `ModelNode`, `SplatNode`, or one of your own — is still called on every frame, in full, and still reaches its children through `super.onFrame`, exactly as before. One visible difference: a callback set on another node, or a node attached, from inside an `onFrame` callback now gets its first tick on the next frame; it used to get it on the same frame only when that node happened to come later in the walk.

- **Seven false tool counts on the live commercial gateway, and the gate that could not see them ([#3189](https://github.com/sceneview/sceneview/issues/3189)).** `mcp-gateway/src/dashboard/` — the pricing page a subscriber reads and the docs page the gateway serves — sat outside every pathspec of `check-mcp-tool-claims.js`, exactly the way `.cursorrules` sat outside the archived-mirror gate. Same blind spot, same outcome: `docs.tsx` advertised "27 Pro tools" twice and "27 free tools" twice, and `pricing.tsx` claimed "27 free tools", "(27 tools…)" and — worst of the set — **"4 vertical packages … 24 specialised tools"** against a real **5 packages and 35 tools**, contradicting `tiers.ts`'s own `PRO_UPGRADE_MESSAGE` on the same funnel and *underselling* the paid tier by a whole package. All seven now derive from source: 29 free / 38 Pro / 67 mounted on the gateway, 28 free of 31 in the npm package, 35 across the five verticals. The gate scans the dashboard (115 prose files, up from 109), its count pattern now allows a qualifier between the number and the noun — "27 **free** tools" walked past the first version while "27 tools" was caught, which reads as coverage without being it — and the vertical aggregate and package count join the derived set so a true claim cannot be rejected.
- **`docs/docs/llms-full.txt` no longer calls itself the complete API reference.** Its first line read "SceneView — Complete API Reference for AI Systems" on a **292-line** file, while the actual complete reference, `llms.txt`, is 7,619 lines. Any agent following the `llms.txt` convention fetched 4% of the API believing it had all of it — a thesis-level defect for an SDK whose stated test is whether an AI can read this and emit working code. The header now says which file is which and points at the full one. The names stay inverted and the URLs stay put: they are load-bearing for external consumers, and renaming them was never the cheap fix — the header was.

<!-- category: Changed -->
- **AR: apps can opt into dragging a floor placement beyond the detected plane.** Set `AutoPlacementState.allowsOffPolygonFloorDrag = true` when the host knows the support is a floor; the drag then slides at the object's height, as in model-viewer's WebXR mode, and reaches 5 m instead of 3. The safe default stays inside the polygon because ARCore's lowest plane may still be a table. The first automatic placement still needs a detected plane within 3 m; walls are unchanged.
- **AR: `AutoPlacementScene` gestures work anywhere on screen.** One finger drags the placed object and two fingers twist and pinch it without landing on it first, as in AR Quick Look and model-viewer; a double tap anywhere toggles 100 %. A tap on empty space still deselects.
- **AR: `AutoPlacementScene` takes the ARCore session hooks and viewport controls** — `cameraStream`, `surfaceType`, `isOpaque`, `sessionConfiguration`, `onSessionCreated`, `onSessionResumed`, `onSessionPaused`, `onSessionUpdated`, `onSessionFailure` and `lifecycle`, as `ARSceneView` names them, plus a `sceneContent` slot for nodes that do not wait for the placement (a resolved cloud anchor) — so a feature that needs cloud anchors, depth, a composited background or its own frame loop keeps the standard placement instead of rebuilding it. Code compiled against 4.72 keeps working.
- **Android demo: AR Placement is one screen with no mode switch.** The Place, Free pose and One call modes were the same placement written three ways; the screen now runs on `AutoPlacementScene` itself, so it gets the SDK's floor drag and full-screen gestures. Links to `ar-pose`, `placement-scene`, `?tab=free-pose` and `?tab=one-call` open it.

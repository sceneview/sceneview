- **`check-sceneview-swift-urls.sh` now allows `changelog.d/*.md`, closing a hole opened by the move to changelog fragments ([#3068](https://github.com/sceneview/sceneview/pull/3068)).** The allowlist covered `CHANGELOG.md` — historical entries about the archived SPM mirror are legitimate — but not `changelog.d/`, even though `collate-changelog.sh` merges each fragment *into* `CHANGELOG.md` and deletes it. A release note explaining the mirror's retirement was therefore blocked while it lived in `changelog.d/` and allowed the moment it was collated: the same sentence, two verdicts. Caught by this PR's own fragment, which failed `Repo hygiene checks`, `Quality gate (full)` and `CI Gate` on a single root cause. The gate stays strict everywhere else — a `sceneview-swift` URL added to any non-allowlisted file still fails and is named.

- **`impact-check.sh`'s SPM gate now measures the repository instead of the disk, and checks the coordinate users actually resolve ([#3068](https://github.com/sceneview/sceneview/pull/3068)).** The check reported `[FAIL] SPM version refs stale — 15 file(s)` on a clean tree, and the 15 files were unfixable by any PR: `grep -r .` walked the working directory, so every hit was an **untracked** local file — marketing drafts that were never committed, plus browser-duplicate copies (`gpt-instructions (1).md`, `qa-drafts (1).md`) whose canonical originals were already correct. The count drifted with the disk (15, then 17) because it never described the repository. Meanwhile the pattern matched only `sceneview/sceneview-swift`, the mirror archived in PR #1215 — bumping a version onto a dead URL is not a fix, and banning that URL outright is already `check-sceneview-swift-urls.sh`'s job (#1237). Excluding the migration guide and changelog left the gate a **tracked population of zero**, so in CI it printed `PASS` while verifying nothing, blind to the 17 tracked files (`llms.txt`, `gpt/knowledge-*.md`, `docs/docs/quickstart-ios.md`, `agents/sceneview-ios/`, …) that carry the canonical `sceneview/sceneview` snippet. The gate now discovers via `git ls-files`, targets the canonical coordinate, names the offending files instead of printing a bare count, and treats an **empty discovery as FAIL** — a scan that matches nothing can no longer report green. `CHANGELOG.md`, `MIGRATION.md` and `docs/docs/migration.md` stay excluded (they quote old versions on purpose), as does `mcp/` (independent release track, and its `ios-outdated` fixture is stale by design). An empty population is split by two sentinel files into "no doc surface checked out" (SKIP — lean/sparse clones are the standard batch-agent workflow, and false-FAILing them under `--fail` is the #2370 scar this script already carries) and "surface present, pattern still matches nothing" (FAIL). Four cases in `test-impact-check.sh` pin the contract: a stale **tracked** ref FAILs and names the file, an aligned one PASSes, stale **untracked** drafts are ignored under `--fail`, and a missing doc surface SKIPs. All four are mutation-proven — restoring the disk scan fails 3 of them (including the original bug, `rc=1` on an untracked draft) and dropping the sentinel fails the lean-clone case. Hardened after agent review (5 warnings, 0 errors): paths stay NUL-delimited from `git ls-files` into a bash array rather than through newline-joined `grep -l` output (BSD `grep -lZ` still terminates with `\n`, so there is no portable NUL-delimited `-l` to bridge with), `grep` calls use `-e … --` so a tracked file named `-i.md` is read as a file and not an option — without it that file is silently dropped from the population, measured — and both regexes accept the same `' " \`` quoting, so `from: '4.26.0'` can no longer be discovered by one and judged stale by the other. A second review round (3 warnings, 0 errors) moved the verdict from the file to the **line**: discovery and check now share one pinning line, so a stale canonical snippet can no longer be excused by an unrelated line elsewhere in the same file quoting the current version — the gate would otherwise confirm a version no reader resolves. Every SPM constraint form is accepted (`upToNextMajor`, `upToNextMinor`, `exact`, not just bare `from:`) instead of being silently dropped from the population; what may sit between the URL and the constraint stays near-adjacent rather than `.*`, because a permissive gap turned every `github.com/sceneview/sceneview/blob/…` prose link into a stale pin (measured: 25 files, 10 of them prose); `CHANGELOG.md`/`MIGRATION.md` are excluded at any path depth, since the reason they are excluded is what the file *is*; and the version is ERE-escaped rather than assumed to be bare semver. Two more mutation-proven cases pin the first and third of those. On the working copy that reported the blocker, the same tree goes from `[FAIL] 15 file(s)` to `[PASS] 17 tracked file(s) scanned`.

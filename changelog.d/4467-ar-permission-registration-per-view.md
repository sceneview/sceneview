- **Two `ARSceneView`s in one activity no longer share one camera-permission registration (Android)** — every AR view registered its permission launcher under the same activity-result key and never unregistered it, so with two AR views alive in one activity (two AR routes in a back stack, a pager, a split layout) the answer to a request made by one went to the other or was dropped. The handler `ARSceneView` builds for itself now registers under a key of its own, saved with the view, and is unregistered when the view leaves composition. Because the key is saved, a request whose dialog is still up when the activity is recreated (a rotation) is answered to the recreated view, which takes that request over instead of launching a second one. An `ActivityARPermissionHandler` you build yourself and pass as `permissionHandler` behaves as before: one activity-wide key, never unregistered — keep at most one per activity. No public signature changes (#4467)

- **`ModelLoader` checks a glTF against the release-build preconditions of gltfio before handing it over ([#4824](https://github.com/sceneview/sceneview/pull/4824)).** gltfio only validates a glTF in debug builds; in a release build a malformed file reaches `createAsset` or `asyncBeginLoad` unchecked, and a failed Filament precondition aborts the whole process, out of reach of any `try`. Before any of these calls, the loader now refuses a model whose accessors, buffer views or sparse indices reach past their buffer or start at a negative offset (an external `.bin` or a `data:` buffer shorter than it declares included), whose buffers cgltf cannot load (a `.glb` whose BIN chunk is missing or shorter than buffer 0, a `data:` buffer that is not valid base64 or holds a JSON escape, which cgltf decodes raw, a buffer with an absolute `://` URI), whose buffer views read a buffer cgltf leaves without data (a buffer with no `uri` other than buffer 0 of a `.glb`, a buffer whose `uri` is empty, a percent-encoded `uri` that decodes to bytes no resource can be fed under or to the same name as another buffer `uri`, the fallback buffer of a `KHR_meshopt_compression` view, an extension the cgltf of Filament 1.72.1 does not parse), whose indices name a vertex past the vertex count (when their bytes are in the `.glb` or an external `.bin`), whose animation samplers keep their keyframe times in no buffer view, whose primitive attributes or morph targets disagree on their vertex count, whose indices are not tightly packed unsigned integers, whose drawn skin has more than 256 joints, whose animated morph weights exceed 256 targets, or whose drawn texture is larger than the GPU supports. Only what the scene draws is measured: an unused skin, image or material, or the PNG fallback next to a KTX2 or WebP texture, no longer counts. The model is refused like any other model that cannot load: an `IllegalArgumentException` from `createModel*`, `null` from `loadModel`. A file the check itself cannot read is refused as a malformed glTF, never thrown. A sampler whose output count does not match its keyframes is left to gltfio's `Animator`, which checks it in every build and turns the model's animations off without crashing. The check never parses the JSON whole: each embedded `data:` URI is cut to its first 64 KiB before the parse, so a 50 MiB `.gltf` with an embedded texture costs about 0.5 MiB of heap to check instead of 150 MiB.
- **A `.gltf` whose buffer `uri` is percent-encoded (`my%20model.bin`, as Blender writes it) no longer loads without geometry.** cgltf decodes the `uri` before it looks the buffer up among the resources `ModelLoader` hands gltfio, so the buffer, fed under its raw name only, was never found and the model came back without data. It is now also fed under the decoded name, unless another resource of the model has that name (cgltf then reads that one, as before, and its length is the one checked), nor when two buffer `uri`s decode to it (`a%20b.bin` and `a%20%62.bin`): gltfio keeps only the last resource fed under a name, so neither is fed under it, and a buffer view reading either is refused; images are fed under their `uri` as written only, which is how gltfio looks them up. The resolver still receives the `uri` as written. Such a model loads when its resolver serves the decoded name: a `file://` or `http(s)` load, or a custom resolver that decodes it. The asset and `File` resolvers open the literal `my%20model.bin`, so with them the file must exist under that encoded name; otherwise the load fails as for any missing buffer: an `IllegalArgumentException` from `createModel*`, `null` and a logged warning from `loadModel`. A `uri` that decodes to bytes no resource can be fed under (not UTF-8, a NUL, or a character outside the BMP, such as `caf%E9.bin`) is refused when a buffer view reads it.
- **`ModelLoader` no longer touches the `Engine` after it is gone.** `updateLoad()`, `progress`, `isLoading` and `destroyModel` do nothing native once the loader or its `Engine` is destroyed, so a frame or a deferred destroy that runs after a dispose no longer reads freed memory. `destroy()` can be called twice.
- **`createInstance` keeps accepting a model created by another `ModelLoader`**, and refuses a destroyed model, or one whose destroy is waiting for its textures, with an `IllegalStateException` instead of reading freed memory.

<!-- category: Changed -->
- **`createModel`, `createInstancedModel` and `createInstance` throw an `IllegalStateException` once the `ModelLoader` or its `Engine` is destroyed**, instead of crashing inside the JNI. A glTF Filament cannot load in a release build throws an `IllegalArgumentException` that lists every reason; one whose JSON is too large to parse (out of memory) or nests too deeply is refused the same way. `loadModel` parses the JSON off the main thread; the synchronous `createModel*` parse it on the calling thread. Read off the main thread, `progress` and `isLoading` return the last value read on it.
- **What the check does not cover:** indices and sparse indices stored in a `data:` buffer, the images such a buffer holds, buffer views compressed with `EXT_meshopt_compression`, a `data:` URI whose header escapes its comma, a buffer `uri` containing a JSON escape (`\uXXXX`, `\/`), which is checked on its unescaped form while cgltf sees the raw string, an `EXT_meshopt_compression` fallback buffer whose `uri` is empty or cannot be fed, a raw (not percent-encoded) `uri` holding a character outside the BMP, which JNI feeds under a name cgltf does not look up, iridescence and anisotropy textures (gltfio does not bind them, so it never decodes them), a texture that fails to decode during `updateLoad()`, an accessor without a buffer view whose `count` is too large to allocate, an unused accessor whose `componentType` is unknown, an animation sampler whose keyframe times have no buffer view when another animation of the model fails gltfio's checks, an external buffer whose file cannot be read before the load, and the size of a WebP image, which is not measured. Other native aborts still need a symbolicated trace to be traced back to their input.

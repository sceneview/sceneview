- **`ModelLoader` checks a glTF against the release-build preconditions of gltfio before handing it over ([#4824](https://github.com/sceneview/sceneview/pull/4824)).** gltfio only validates a glTF in debug builds; in a release build a malformed file reaches `createAsset` or `asyncBeginLoad` unchecked, and a failed Filament precondition aborts the whole process, out of reach of any `try`. Before any of these calls, the loader now refuses a model whose accessors, buffer views or sparse indices reach past their buffer or start at a negative offset (an external `.bin` or a `data:` buffer shorter than it declares included), whose buffers cgltf cannot load (a `.glb` whose BIN chunk is missing or shorter than buffer 0, a `data:` buffer that is not valid base64), whose indices name a vertex past the vertex count (when their bytes are in the `.glb` or an external `.bin`), whose animation samplers keep their keyframe times in no buffer view, whose primitive attributes or morph targets disagree on their vertex count, whose indices are not tightly packed unsigned integers, whose drawn skin has more than 256 joints, whose animated morph weights exceed 256 targets, or whose drawn texture is larger than the GPU supports. Only what the scene draws is measured: an unused skin, image or material, or the PNG fallback next to a KTX2 or WebP texture, no longer counts. The model is refused like any other model that cannot load: an `IllegalArgumentException` from `createModel*`, `null` from `loadModel`. A file the check itself cannot read is refused as a malformed glTF, never thrown. A sampler whose output count does not match its keyframes is left to gltfio's `Animator`, which checks it in every build and turns the model's animations off without crashing. The check never parses the JSON whole: each embedded `data:` URI is cut to its first 64 KiB before the parse, so a 50 MiB `.gltf` with an embedded texture costs about 0.5 MiB of heap to check instead of 150 MiB.
- **`ModelLoader` no longer touches the `Engine` after it is gone.** `updateLoad()`, `progress`, `isLoading` and `destroyModel` do nothing native once the loader or its `Engine` is destroyed, so a frame or a deferred destroy that runs after a dispose no longer reads freed memory. `destroy()` can be called twice.
- **`createInstance` keeps accepting a model created by another `ModelLoader`**, and refuses a destroyed model, or one whose destroy is waiting for its textures, with an `IllegalStateException` instead of reading freed memory.

<!-- category: Changed -->
- **`createModel`, `createInstancedModel` and `createInstance` throw an `IllegalStateException` once the `ModelLoader` or its `Engine` is destroyed**, instead of crashing inside the JNI. A glTF Filament cannot load in a release build throws an `IllegalArgumentException` that lists every reason; one whose JSON is too large to parse (out of memory) or nests too deeply is refused the same way. `loadModel` parses the JSON off the main thread; the synchronous `createModel*` parse it on the calling thread. Read off the main thread, `progress` and `isLoading` return the last value read on it.
- **What the check does not cover:** indices and sparse indices stored in a `data:` buffer, the images such a buffer holds, buffer views compressed with meshopt, iridescence and anisotropy textures (gltfio does not bind them, so it never decodes them), a texture that fails to decode during `updateLoad()`, an accessor without a buffer view whose `count` is too large to allocate, and the size of a WebP image, which is not measured. Other native aborts still need a symbolicated trace to be traced back to their input.

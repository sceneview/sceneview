- **`rememberCameraManipulator(orbitHomePosition, targetPosition)` now honours new inputs.** It was keyless (`remember(creator)`), so a new eye or target was silently ignored after the first composition and resetting the view needed a `key { }` block around the call. It is now keyed on `orbitHomePosition` and `targetPosition`, compared by value, like the `orbitRadius` overload: a new value rebuilds the manipulator and `SceneView` glides the camera there, while an equal `Position(…)` re-created on recomposition changes nothing. Both overloads gain a `key: Any? = null` parameter that rebuilds the manipulator on demand — "double-tap to reset the view" is now `rememberCameraManipulator(orbitRadius = 3f, key = resets)` with `resets++` in `onDoubleTap`, and it is how a new `creator` takes effect (a lambda instance is not a key: it changes on recomposition whenever it captures a re-created value). `SceneView`'s own default manipulator still reads the camera node's position once and never rebuilds; don't pass `orbitHomePosition = cameraNode.worldPosition` yourself, that value moves on every orbit. Source- and binary-compatible: the overloads without `key` stay public, so every call that does not name `key` — positional ones included, such as `rememberCameraManipulator(eye, target, Inertia.None, factory)` — resolves to them and keeps its meaning.

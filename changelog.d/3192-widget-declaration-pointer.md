- **The MCP Apps widget pointer travelled on tool *results* only, never on the *declaration* ([#3192](https://github.com/sceneview/sceneview/issues/3192)).** `tools/list` returned every mounted tool with zero `_meta.ui.resourceUri` occurrences, so a host that decides what UI to render by reading the tool list never learned the widget existed — it could only find out by calling `view_3d_model` first, which is the wrong way round: the point of the declaration pointer is that the host can preload the UI before the first call. Both sides now go through one `withWidgetPointer()` helper, so a future widget can no longer be added to one half and forgotten on the other. The list maps over copies: `getAllTools()` hands back the registry's own definition objects, and stamping `_meta` onto them would mutate the shared registry for the Worker's whole lifetime — a mutation the response would still look correct through, which is why it has its own test that reads the registry rather than the response.
- **The `extensions` / `io.modelcontextprotocol/ui` capability is deliberately still not declared in `initialize`**, and the reason is now written where the next reader will look. It belongs to protocol revision `2026-07-28` while the gateway negotiates `2025-03-26`; advertising one revision's extension while negotiating another is a claim the server cannot honour. It is not a prerequisite for the widget — the declaration pointer above is what a host actually reads — so it lands with the protocol bump rather than ahead of it.

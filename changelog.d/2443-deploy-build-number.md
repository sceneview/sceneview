- **macOS App Store demo-app upload no longer rejected for a too-low `CFBundleVersion` (#2443).** The iOS-demo Xcode project pinned `CURRENT_PROJECT_VERSION` as a static literal (build `366`), so every store-affecting deploy re-archived the *same* build number; App Store Connect refused it on the Mac App Store stream ("`CFBundleVersion` … must contain a higher version than that of the previously uploaded version [366]"). `app-store.yml` now derives `BUILD_NUMBER=$(date -u +%Y%m%d%H%M)` — a UTC timestamp — and passes `CURRENT_PROJECT_VERSION="$BUILD_NUMBER"` into the `xcodebuild archive` invocation for **both** the iOS and macOS legs. A command-line build setting overrides the project-file literal at archive time, and a wall-clock timestamp (`2026…`) is always strictly increasing *and* always far above any historical build number (≫ 366), with no run-counter reset to break it. No change to `project.pbxproj` (the static literal is now irrelevant at archive time); the marketing version `MARKETING_VERSION = 4.18.0` and the `sync-versions.sh` check that guards it were already correct.

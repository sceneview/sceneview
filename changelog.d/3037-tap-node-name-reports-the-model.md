- **A tap on a model now reports the model on iOS, not a mesh inside it ([#3037](https://github.com/sceneview/sceneview/pull/3037)).** Tapping `black_dragon.usdz` in the Flutter demo on an iOS 26 simulator reported `skin0` — the name of an internal mesh — while the same tap on Android reports `black_dragon`. `SpatialTapGesture` hands back the deepest hit entity, and the Flutter bridge walked up to the first *named* ancestor; USD assets name their meshes, so the walk stopped inside the asset and never reached the model root the bridge itself had named. The React Native iOS bridge had the same bug in a blunter form: it reported `hit.entity.name` raw, with no walk at all. Android cannot reproduce either: the only collider a loaded model owns is the `ModelNode` root (glTF child renderables get no collision shape), so its hit-test can only ever resolve to the model. **The resolution now lives in `SceneViewerHostView`**, which owns the content root and knows which entity is a model, so every caller of the shared host inherits it instead of each bridge carrying its own walk. Its `onTapModel` hands over the model root — or `nil` when the tap landed on no model at all, a case neither bridge could previously express.
- **The name a tap reports is derived in one place, the way Android derives it.** `sceneViewerNodeName` strips any query and fragment, takes the last path component and drops the extension, mirroring the Kotlin bridges' `tapNodeName` / `ModelNodeData.nodeName`. That query strip is not cosmetic: a model source may be a URL (`ModelLoader` loads `https://` on Android), and cutting at the last `.` only strips the extension when it is the last dot in the whole string — `https://cdn/robot.glb?sig=SIG&v=1.2` derived `robot.glb?sig=SIG&v=1`, putting a CDN signature into a payload apps routinely show in a label or send to analytics. The Swift and Kotlin derivations agree for every `.glb` / `.gltf` / `.usdz` source; they diverge only on degenerate inputs neither bridge can load (a trailing slash, a dotfile base name), which the doc comments on both sides spell out.
- **The React Native Android bridge named no model at all**, so its `TapEvent.nodeName` was `null` for *every* tap, on a model or not. Each model is now named after its file, so both platforms emit the identical string. That Kotlin is compiled in CI as of [#3043](https://github.com/sceneview/sceneview/pull/3043) (`rn-android-compile.yml`), so it is checked against real artifacts rather than read-only.

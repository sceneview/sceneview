<!-- category: Added -->
- **Load progress and clear errors for large GLBs ([#4823](https://github.com/sceneview/sceneview/pull/4823)).** `ModelLoader.awaitModelInstance` returns once every texture is final (or, if no texture progresses for 10 s, with what it has, logged) and reports `Reading`, `Creating` and `Textures` progress on the main thread; `rememberModelLoadState` exposes the same load as `Loading(progress)`, `Ready` or `Failed` in Compose. Both refuse a model whose `extensionsRequired` names an extension gltfio cannot load, such as `EXT_texture_avif`, `KHR_meshopt_compression` or gltfpack `-mi`'s `EXT_mesh_gpu_instancing`, before any Filament call: `awaitModelInstance` throws `UnsupportedGltfExtensionException` (its `extensions` names what is missing) and `rememberModelLoadState` reports it as `Failed`. The new `ModelLoader.SUPPORTED_GLTF_EXTENSIONS` lists the extensions gltfio 1.72.1 actually loads and renders, leaving out those it parses but does not render (`KHR_materials_anisotropy`, `KHR_materials_iridescence`, `KHR_materials_diffuse_transmission`, `EXT_mesh_gpu_instancing`). Local files and assets are read into one array of their size, which halves the Java heap peak of a load (108 to 54 MB for a 53 MB model).

<!-- category: Changed -->
- **`ModelLoader` finishes loads it used to leave hanging, and says what it cannot render ([#4823](https://github.com/sceneview/sceneview/pull/4823)).** No existing API throws anything new: a model whose `extensionsRequired` names an extension gltfio cannot load is now logged by the existing `create*`, `load*` and `load*Async` calls, which return it as before. A `.gltf` whose external texture is missing no longer leaves the load (and `isLoading`) unfinished: the texture is logged and skipped by feeding gltfio a 1-byte stand-in for it. As a consequence, feeding that image yourself later with `resourceLoader.addResourceData(uri, data)` no longer works; resolve it through the `resourceResolver` instead. WebP textures stored as separate `.webp` files beside a `.gltf` are now converted to PNG like embedded ones, within the same 256-image budget, and one that cannot be decoded is logged by name; only declared images are converted, never a buffer.

<!-- category: Fixed -->
- **WebP glTF textures now actually render on Android ([#4823](https://github.com/sceneview/sceneview/pull/4823)).** The converted model declared its PNG as `image\/png` (Android's `org.json` escapes `/`, and gltfio reads `mimeType` verbatim), so gltfio found no decoder for it and skipped the texture: the model loaded untextured, with no error. The rewritten glTF JSON now writes its slashes unescaped.

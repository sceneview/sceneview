<!-- category: Added -->
- **Load progress and clear errors for large GLBs ([#4823](https://github.com/sceneview/sceneview/pull/4823)).** `ModelLoader.awaitModelInstance` returns once every texture is final and reports `Reading`, `Creating` and `Textures` progress on the main thread; `rememberModelLoadState` exposes the same load as `Loading(progress)`, `Ready` or `Failed` in Compose. A model whose `extensionsRequired` names an extension gltfio cannot load, such as `EXT_texture_avif` or `KHR_meshopt_compression`, is now refused before any Filament call instead of rendering untextured without a word: `awaitModelInstance` throws `UnsupportedGltfExtensionException` (its `extensions` names what is missing) and `rememberModelLoadState` reports it as `Failed`. `ModelLoader.SUPPORTED_GLTF_EXTENSIONS` lists what works. Local files and assets are read into one array of their size, which halves the Java heap peak of a load (108 to 54 MB for a 53 MB model).

<!-- category: Changed -->
- **`ModelLoader` refuses a model it cannot render, through the failures its APIs already report ([#4823](https://github.com/sceneview/sceneview/pull/4823)).** No existing API throws anything new. When a model's `extensionsRequired` names an extension gltfio cannot load, the suspend `loadModel` and `loadModelInstance` now return `null` and `loadInstancedModel` an empty list, logged, like the `load*Async` calls and `rememberModelInstance`, where they used to return an untextured model; the synchronous `createModel(buffer)`, `createModelInstance(buffer)` and `createInstancedModel(buffer)` reject it with the `IllegalArgumentException` they already declare (an `UnsupportedGltfExtensionException`). A `.gltf` whose external texture is missing no longer leaves the load (and `isLoading`) unfinished: the texture is logged and skipped. `SUPPORTED_GLTF_EXTENSIONS` no longer lists `KHR_materials_anisotropy`, `KHR_materials_iridescence`, `KHR_materials_diffuse_transmission` and `EXT_mesh_gpu_instancing`, which gltfio parses but does not render.

- **Android**: `Frame.cameraImage()` now returns `null` instead of throwing when ARCore has no image to give: a stale frame (`DeadlineExceededException`), a full CPU image pool (`ResourceExhaustedException`), or warm-up (`NotYetAvailableException`). `Frame.captureCameraBitmap()` inherits the same behaviour. The AR Image demo's "Capture this view" no longer crashes: the tap now asks for the next frame, which acquires the image in the render callback and converts it off the main thread. The ML Object Label demo no longer re-throws camera image failures from its render callback; a failed frame is skipped. The `captureCameraBitmap` and `RuntimeAugmentedImageDatabase` KDoc samples no longer show the stale-frame pattern.
- **Android**: the ML Object Label demo keys its labels on their anchor. Evicting the oldest of its six labels used to rebuild every other label and destroy their billboards twice, the most likely cause of the crash reported once four or more objects were labelled.

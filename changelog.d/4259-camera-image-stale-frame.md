- **Android**: `Frame.cameraImage()` now returns `null` instead of throwing when ARCore has no image to give: a stale frame (`DeadlineExceededException`), a full CPU image pool (`ResourceExhaustedException`), or warm-up (`NotYetAvailableException`). `Frame.captureCameraBitmap()` inherits the same behaviour. The AR Image demo's "Capture this view" no longer crashes: the tap now asks for the next frame, which acquires the image in the render callback, converts it off the main thread and always closes it, even when the screen is left first. The `captureCameraBitmap` and `RuntimeAugmentedImageDatabase` KDoc samples show the same pattern instead of the stale-frame one.
- **Android**: a full CPU image pool now returns `null` to the caller instead of throwing, which can hide an image leak on the caller's side (every acquired `Image` must be closed); the caller gets no exception, and the event is logged at WARN under the `SceneView.CpuImage` tag.
- **Android**: `destroy()` is now a no-op on an already destroyed node for every node type. The subclass overrides (`RenderableNode`, `ImageNode`, `MeshNode`, `GeometryNode`, `LightNode`, `ViewNode`, `VideoNode`, `ContactShadowNode`, and the AR face, hand, point-cloud, depth-mesh, shadow-plane and cloud-anchor nodes) ran their own teardown again before reaching the guard in `Node.destroy()`: a second call destroyed the renderable or light component again, re-enqueued textures and invalidated every other node's cached component handles.
- **Android**: the ML Object Label demo keys its labels on their anchor. Evicting the oldest of its six labels rebuilt every other label and destroyed their billboards twice. This does not fix the separate "Invalid texture still bound to MaterialInstance" abort, which is tracked on its own. Its render callback also no longer re-throws camera image failures (a cleanup: `ARSceneView` already caught them).

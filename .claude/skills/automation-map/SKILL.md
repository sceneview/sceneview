## Automation ecosystem

### Hooks (settings.json)

Hooks trigger automatically on specific Claude Code actions:

| Trigger | When | Action |
|---|---|---|
| Pre-commit version check | `git commit` | Blocks if VERSION_NAME mismatches across modules |
| Post-edit gradle.properties | Any gradle.properties edit | Reminds to update ALL version locations |
| Post-edit Android API | Edit in `sceneview/src/` | Reminds to check SceneViewSwift + llms.txt |
| Post-edit Swift API | Edit in `SceneViewSwift/Sources/` | Reminds to check Android + llms.txt |
| Post-push reminder | `git push` | Reminds to update CLAUDE.md and website |

### Scripts (.claude/scripts/)

| Script | Purpose |
|---|---|
| `sync-versions.sh` | Scan ALL version declarations, report/fix mismatches (the single source of truth for the version-location list) |
| `claim.sh` | Atomic issue-claim registry that kills the #2300 dup-implementation race. Primary lock = GitHub `in-progress` label (cross-host); local mirror = the `STATE.md` IN-FLIGHT ledger. `<issue#>` / `--check` / `--release` / `--list` / `--force`. macOS-safe (sleepless `mkdir` lock, no `flock`) |
| `check-saved-workflows.sh` | Static validator for the `.claude/workflows/*.js` saved workflows (async-wrapped `node --check` + meta block + resume-safety). Distinct from `check-workflow-scripts.sh`, which validates the CI YAML |
| `cross-platform-check.sh` | Compare Android vs iOS vs Web API surface, report gaps |
| `release-checklist.sh` | Pre-release validation (versions, changelog, tests, etc.). Section 6 runs `check-breaking-change-bump.sh` (BLOCKING — a missing guard is a FAIL, not a WARN: unchecked must never read as clean); section 16 runs `store-preflight.sh` (advisory); section 17 runs the store-sync listing-drift diff (`play_listing.py` / `asc_listing.py --dry-run --fail-on-drift`, advisory WARN — never a blocker, #2612 Phase C) |
| `collate-changelog.sh` | Collates `changelog.d/*.md` into a new `## vX.Y.Z` section, then DELETES the fragments. Two guarantees beyond bucketing: (1) **every HTML comment is stripped** — only `<!-- category: X -->` has meaning, everything else is a maintainer-only note that must never reach the public page. Before #3037 the loop intercepted the category tag and copied the rest verbatim, so a nine-line internal note (sign-off, publish-rn/`GITHUB_REF_NAME` mechanics) was one release away from shipping as user-facing notes; it was deleted by hand. An unterminated `<!--` is a hard ERROR, not a silent truncation — bullets vanishing from a section nobody diffs, with the source already deleted, is worse than the leak. (2) It **invokes `check-breaking-change-bump.sh` before writing anything**, and refuses to run if that script is absent (#2988 — absence must not read as pass). Shares `lib/changelog-fragment.sh` with the guard so both judge the same text. A delimiter inside a Markdown **code span** is literal text: the first fragment written after the stripper landed said ``an unterminated `<!--` is a hard error``, whose backticked delimiter opened a comment that ate the next category tag and refiled two bullets. Self-tested by `test-collate-changelog.sh`, three mutation tests (per-tag flush; no-op stripper; code-span-blind stripper) |
| `check-breaking-change-bump.sh` | Refuses a PATCH-level release that carries a breaking change (#3037). `release.yml`'s `publish-rn` derives the npm version straight from the tag (`VERSION=${GITHUB_REF_NAME#v}`), so `v4.26.1` would publish a source-breaking `.d.ts` change to `@sceneview-sdk/react-native` as a semver patch — the class every caret range takes without review. A fragment declares breaking explicitly (`<!-- breaking -->` / `<!-- breaking: true\|false -->`) **or in its public prose**; the prose path is what matters, since #3037's own fragment says "source-breaking … never a patch" in English and predates the marker. Negations (`non-breaking`) and `groundbreaking` are excluded, both taken from real fragments; `<!-- breaking: false -->` is the opt-out and always wins. Category-independent on purpose — a `Removed` public symbol is as breaking as a `Changed` one. Previous version comes from `CHANGELOG.md`, skipping a section that names the target, so it works on BOTH sides of the release bump. Exit 1 = refused, 2 = malformed fragment (bad marker value, unterminated comment) — never a silent pass. **No override flag**: the remedy is to tag the next minor. Wired in three places (`collate-changelog.sh`, `release-fast.yml` right after version validation, `release-checklist.sh` §6). The prose heuristic ignores code spans and folds newlines first, so a backticked `breaking` and a bullet wrapped between `non-` and `breaking` are both inert. A marker value is captured as everything up to `-->`, not as one token, so `<!-- breaking: not sure -->` and `<!-- breaking: -->` are *malformed* (exit 2) rather than "not a marker" — a token-shaped regex made a typo fail to match, get stripped as an ordinary comment, and ship unflagged. Both halves of the prose heuristic are bounded on purpose: code spans are matched as a RUN of backticks (a ``breaking`` written with two would otherwise stay visible) and the negation alternation is left-bounded (unbounded, "piano breaking" reads as "no breaking" and a real declaration passes). The marker is recognised in ANY comment span on a line, not only on a line that is nothing else — anchored to the whole line, a marker trailing a bullet fell through to the stripper and was deleted before the prose heuristic could see it, so a misplaced marker declared nothing at all. Detection runs on a code-span-stripped copy of the line, so a doc fragment quoting the marker in backticks stays inert. Self-tested by `test-check-breaking-change-bump.sh` (31 assertions) with a mutation test per direction |
| `lib/changelog-fragment.sh` | Sourced fragment-parsing primitives shared by the collator and the breaking guard (`frag_strip_comments_line`, `frag_is_category_tag_line`, `frag_is_breaking_marker_line`, `frag_prose_claims_breaking`). The stripper writes to a global rather than echoing: `x="$(f "$line")"` runs in a subshell and would drop the multi-line comment state on every line, silently restoring the verbatim-copy bug |
| `store-preflight.sh` | Read-only App Store Connect preflight (#2612 P1) — detects the human-only store blockers that silently 403 a deploy: an expired Apple agreement (`REQUIRED_AGREEMENTS_MISSING_OR_EXPIRED` canary), an App Review rejection, cert/profile expiry (< `CERT_EXPIRY_WARN_DAYS`, default 30), and (since #2731) an open never-submitted reviewSubmission (`READY_FOR_REVIEW`/`UNRESOLVED_ISSUES`) — the silent-submission signature the IOS-scoped version-state probe alone can't see. Signs the ASC ES256 JWT with openssl only; reuses `app-store.yml`'s ASC secrets (no new scope); SKIPs honestly without creds. Advisory-first — a blocker hard-blocks only under `GATE_HARD=1`. Wired into `release-checklist.sh` §16, the `/store-status` command doc (probe-set wiring is a P1 follow-up), and a daily `maintenance.yml` job. Self-tested by `test-store-preflight.sh` (in `repo-hygiene`) |
| `test-app-store-submit.py` | Hermetic self-test for `app-store.yml`'s **Submit build for App Store review** step (#2893). That step is a large Python program inside a YAML heredoc, and it had no test seam: exercising it meant dispatching the workflow, which archives, signs and uploads a real TestFlight build — so every fix to it was validated in production, on a release, after it broke one (#2731, #2885, #2893). The test EXTRACTS the real heredoc (never a copy, so it cannot drift; a renamed step fails loudly instead of silently covering nothing) and runs it against a stubbed App Store Connect: build selection pinned to `ASC_EXPECTED_BUILD` (W1), auth-vs-transient classification on the builds GET (W2), orphan-`reviewSubmission` cleanup on any post-create failure (W5), and the `whatsNew` sourcing. Stdlib only — no network, no secrets, no Apple call. Runs in `ci.yml` → `repo-hygiene` |
| `store-sync/play_listing.py` | Play listing sync/diff as code (#2612 P2) — the single code path for `play-store.yml`'s `sync-listing` job (`--apply`) and local read-only drift diffs (`--dry-run` default: listing text + per-image SHA-256 vs the live store, probe edit abandoned). SKIPs honestly without creds. Self-tested by `test-store-sync.sh` (repo-hygiene) |
| `store-sync/asc_listing.py` | App Store listing drift diff + screenshot upload (#2612 P2). `--dry-run` (default, read-only) diffs live ASC text fields + screenshot `sourceFileChecksum` against `samples/ios-demo/distribution/app-store/` + `appstore-screenshots/`; `--apply-screenshots` uploads the repo screenshots (reserve → chunked PUT → commit `uploaded:true` + MD5) to the **editable** version, replacing each display-type set (delete-then-upload; a failed delete is fatal *before* any upload, so a half-replaced set can't happen). Live order is *expected* to follow repo filename order — Apple does not promise creation order, so the script PROBES it after upload and warns instead of asserting. Never creates a version — SKIPs honestly when none is editable. Listing TEXT stays owned by `app-store.yml`'s submit step. TWO CI callers since #2899: (1) `app-store.yml`'s submit step calls `apply_screenshots()` **inline**, between the listing-text sync and the review submission — the only moment an editable version exists, since that step creates it and Apple locks the metadata on submission; every release goes through this path, and it is deliberately never fatal (`except BaseException` — the function signals failures with `SystemExit`) so a screenshot cannot stop a release reaching App Review; (2) `app-store-screenshots.yml` (ubuntu, dispatch-only, no Xcode) remains for out-of-band refreshes, and can only write when a version happens to be open. Do NOT collapse (1) back into (2) by symmetry with the old note here: a dispatch-only caller writes only by luck, which is how v4.26.0 shipped a set four releases stale. `app-store.yml` still must not be *dispatched* merely to refresh screenshots — its `deploy-ios`/`deploy-macos` are gated only on `*_ready`, so that would also build and upload a TestFlight build (PR #2781 review). Flag abbreviations are disabled on both store-sync scripts: `--apply` must not resolve into an upload. Same ASC env aliases as `store-preflight.sh`. **`--dry-run` is also the daily read-only `maintenance.yml` `asc-listing-drift` job** (#2612 P2 Phase C step 0, sibling of `store-preflight`) — the first CI caller of the ASC read-only path. It prints a `sourceFileChecksum` **provenance verdict** (`confirmed`/`unattested-match`/`md5-shaped`/`absent`/`other`/…): the MD5 keying the screenshot diff rests on is *measured, not assumed* (true by construction for anything this script uploaded — Apple echoes what we declare — so only console-sourced live sets are an honest sample). A repo-MD5 match therefore reports `unattested-match`, **not** `confirmed`, unless the operator attests provenance with `--screenshots-are-console-sourced` (which covers the draft too, and names its own source in the log so an inherited env var can't attest invisibly); without that gate a single `app-store-screenshots.yml` dispatch would have made the verdict permanently green on a tautology (caught in PR #2811 review). The probe also samples the **editable draft**'s screenshot sets and stamps every set with the version it was read from (`APP_IPHONE_67 @4.23.0`, `… @draft 4.24.0`), because a console upload lands on the draft — and that draft keeps its screenshots when it ships, so a set being live proves nothing about who uploaded it. Phase C's drift gate is now **wired on both surfaces, advisory**: §17 of `release-checklist.sh` WARNs at release time (NOT gated on a `confirmed` verdict — an advisory WARN is not the blocking bar, PR #2880), and the daily `maintenance.yml` `listing-drift` / `asc-listing-drift` jobs run the diff with `--fail-on-drift` and open a de-duplicated per-store tracking issue **only on a measured drift** (exit 3 — never on a credential-less skip or a mid-read crash), refreshed daily while the drift persists — and **auto-closed once the diff comes back clean** (#2835), through the shared `close-maintenance-issue.sh`. The close is gated on a *positive* measured-and-clear signal (`clean=1`: exit 0 **and** a non-empty log **and** no `[skip]` line), never on the bare exit 0, because 0 also covers the credential-less skip and a run where the tool never spoke — closing on that would silently retract a live finding the first time a secret expired. #2612 Phase C. Neither fails CI; promotion to blocking waits on n=5 |
| `close-maintenance-issue.sh` | Closes an auto-filed `maintenance.yml` tracking issue once its condition clears (#2835). Called by all five auto-filers (`skill-drift`, `deeplink-health`, `mcp-npm-freshness`, `listing-drift`, `asc-listing-drift`), which were one-directional before it — they opened and refreshed issues daily and never closed one, so #2835 stayed open 13 days after the npm lag it described was gone. Each caller passes its own **positive** measured-and-clear signal (`clean` / `resolved`), never the inverse of the open signal: for both store jobs exit 0 also means "credentials absent", and a failed `npm view` yields the same "no lag" as a genuine match. The lookup only ever matches an issue that is open, filed by `app/github-actions`, labelled `maintenance`, and title-matched — a human-filed issue can never be closed by it. `--dry-run` reports the target without touching it |

| `lib/gradle-run.sh` | Sourced helper that runs a Gradle task while KEEPING its output, and classifies the failure before anything names it — THREE classes, not two: **host setup** (`gradle_setup_reason` / `gradle_setup_fix`), **environment** (`gradle_infra_reason`), real failure; plus `gradle_run`, `gradle_log_tail`, `roborazzi_fresh_diff_count`, and the two reporters the gates actually call, `gradle_report_failure` and `script_report_failure`. Exists because `./gradlew <task> --quiet 2>/dev/null` + "any non-zero exit ⇒ <one hard-coded diagnosis>" is a lie generator: measured 2026-08-06, `pre-push-check.sh` reported "Android screenshot regression detected" for a `Gradle build daemon disappeared unexpectedly` (daemon contention), reproduced identically on a pristine clone of `main` — and `2>/dev/null` had deleted the one line that said so. The pattern table is deliberately NARROW: too broad and a genuine compile break gets waved through as "infrastructure", which is the same lie pointing the other way. ⚠️ Never re-add a bare `Could not resolve all …` row — Gradle prints that same line for an unreachable repository AND for a coordinate that does not exist (a code defect); only the transport rows discriminate, and that row is what let a release blocker degrade to a pass in review. `gradle_log_tail`'s trailing `|| true` is load-bearing too, not decoration: `grep -v` exits 1 on an all-boilerplate log, and under `set -euo pipefail` errexit kills the caller AT THE PIPELINE, so a `return 0` at the end of the function never runs. `roborazzi_fresh_diff_count` is the positive-proof half — a verdict on the goldens requires a comparison report NEWER than a marker taken before the run, because the goldens are not declared inputs of any task and a re-run comes back `UP-TO-DATE` having compared nothing. The host-setup class was added by #3065 and is checked FIRST: a fresh worktree has no `local.properties` (gitignored), so every Gradle step died with `SDK location not found` while `pre-push-check.sh` announced "public-API surface drifted" and prescribed `apiDump` — a remedy that commits a bogus `.api` diff. Like an infra failure it means the code was never judged; unlike it, re-running changes nothing, so the row carries the exact FIX (`sdk.dir=` / `ANDROID_HOME`, missing SDK package or licence, missing platform / build-tools / NDK, unusable JDK) and the caller must print it. `gradle_report_failure` reports four outcomes in order — host setup → environment → "died before it compared anything" → real failure — and takes an optional POSITIVE proof cue: apiCheck passes the two strings the Kotlin binary-compatibility validator actually prints (read out of its jar, not guessed), so a build that dies inside `apiBuild` reads as "not compared", never as a drift. That case is real — a poisoned instrumented-transform cache produced exactly it, and the first version of the #3065 fix still called it a drift. `script_report_failure` applies the same rule to the NON-Gradle checkers (steps 9-13): exit >= 2 (or 126/127) is "could not run", a missing cue is "exited without reaching its verdict", and only a checker that printed its own finding gets the finding's name — and a cue must cover EVERY finding path of its checker, including early exits that never reach the tally (step 12). Anything that could not run is counted separately from a failure and still blocks: a gate that did not run is not a gate that passed. Used by `pre-push-check.sh` and `release-checklist.sh`; self-tested by `test-gradle-run.sh` |
| `test-gradle-run.sh` | Hermetic self-test for `lib/gradle-run.sh` (in `repo-hygiene`). Synthetic Gradle logs, no Gradle, no network. Asserts BOTH directions — the daemon/lock/OOM/network/disk fixtures classify as infra, and the compile-break and test-failure fixtures must NOT — plus the four measured Roborazzi report states (fresh clean / fresh with diffs / stale / corrupt), where a stale report must degrade to `unknown` and never to a silent `0`. Since #3065 it also drives the reporters on logs copied from real runs — the `SDK location not found` log, a genuine `.api` drift, a dead `apiBuild` — with the exact arguments step 14 passes, and reads what they PRINT and what they COUNT (a setup failure must never say "drifted", must warn against `apiDump` instead of prescribing it, and must land in the INCOMPLETE bucket). It also reads step 12's proof cue out of `pre-push-check.sh` and requires it to match both of that checker's finding paths. Mutation-tested three ways: with the daemon row deleted from the infra table, with the `SDK location not found` row deleted from the setup table, and with a proof cue that matches anything, the suite has to fail — otherwise its assertions are hollow. It already earned itself once — it caught that `|` could not be the table separator, since it is also the regex alternation operator |

Fetched from the DEFAULT BRANCH via `git show`, never read out of the checkout: same pin as `grade-pr-review.sh`, because a PR that could rewrite the script deciding what the judges read could hand them a diff omitting its own edit. Exists because those four lines were inline and shipped the very defect the reviewers exist to catch — a confident verdict on data that did not establish it. Measured on run 31370116851 (#3076): the job's own `git fetch origin main --depth=1` grafts a `.git/shallow` onto its `fetch-depth: 0` checkout, `origin/main...HEAD` stops resolving, and the old two-dot fallback showed everything `main` had gained since the branch point, REVERSED — 2162 diff lines instead of 797, and a blocking `DO_NOT_MERGE` naming two files the PR never touched.

## Automation ecosystem

### Hooks (settings.json)

`settings.json` declares exactly **two** entries, and both dispatch to
`.claude/scripts/hook-dispatch.sh`. Read that script for the truth; the table
below is its summary, not a second source.

| settings.json entry | Dispatches to | Blocking? |
|---|---|---|
| `PreToolUse` / `Bash` | `hook-dispatch.sh pre-bash` — guards 1 and 2 below | Yes, `exit 2` |
| `PostToolUse` / `EnterWorktree` | `hook-dispatch.sh post-worktree` | No, reminder only |

Only **two** conditions ever block, both deterministic, local and sub-second:

| Guard | Fires on | Blocks when |
|---|---|---|
| 1 — version mismatch | `git commit` | a module `gradle.properties` `VERSION_NAME` differs from the root one |
| 2 — emulator lease (#2862, #2924) | a mutating `adb`/`android` command | the target serial carries a LIVE lease owned by another session. Inherit with `EMU_LEASE_SESSION=…`, or get your own device with `setup-ar-emulator.sh`. `EMU_LEASE_TAKEOVER=1` is refused |

`PostToolUse:EnterWorktree` only reminds you to `claim.sh` the issue and prints
the sibling worktrees. **No post-edit or post-push hook exists** — the five that
did were removed on 2026-08-11 because each fired *after* the action, so it had
no lever, and each re-injected 30–60 words into every later turn. The rule that
replaced them: a hook either BLOCKS or it does not exist.

| `release-checklist.sh` | Pre-release validation (versions, changelog, tests, etc.). Section 6 runs `check-breaking-change-bump.sh` (BLOCKING — a missing guard is a FAIL, not a WARN: unchecked must never read as clean); section 16 runs `store-preflight.sh` (advisory); section 17 runs the store-sync listing-drift diff (`play_listing.py` / `asc_listing.py --dry-run --fail-on-drift`, advisory WARN — never a blocker, #2612 Phase C) |
| `collate-changelog.sh` | Collates `changelog.d/*.md` into a new `## vX.Y.Z` section, then DELETES the fragments. Two guarantees beyond bucketing: (1) **every HTML comment is stripped** — only `<!-- category: X -->` has meaning, everything else is a maintainer-only note that must never reach the public page. Before #3037 the loop intercepted the category tag and copied the rest verbatim, so a nine-line internal note (sign-off, publish-rn/`GITHUB_REF_NAME` mechanics) was one release away from shipping as user-facing notes; it was deleted by hand. An unterminated `<!--` is a hard ERROR, not a silent truncation — bullets vanishing from a section nobody diffs, with the source already deleted, is worse than the leak. (2) It **invokes `check-breaking-change-bump.sh` before writing anything**, and refuses to run if that script is absent (#2988 — absence must not read as pass). Shares `lib/changelog-fragment.sh` with the guard so both judge the same text. A delimiter inside a Markdown **code span** is literal text: the first fragment written after the stripper landed said ``an unterminated `<!--` is a hard error``, whose backticked delimiter opened a comment that ate the next category tag and refiled two bullets. Self-tested by `test-collate-changelog.sh`, three mutation tests (per-tag flush; no-op stripper; code-span-blind stripper) |
| `check-breaking-change-bump.sh` | Refuses a PATCH-level release that carries a breaking change (#3037). `release.yml`'s `publish-rn` derives the npm version straight from the tag (`VERSION=${GITHUB_REF_NAME#v}`), so `v4.26.1` would publish a source-breaking `.d.ts` change to `@sceneview-sdk/react-native` as a semver patch — the class every caret range takes without review. A fragment declares breaking explicitly (`<!-- breaking -->` / `<!-- breaking: true\|false -->`) **or in its public prose**; the prose path is what matters, since #3037's own fragment says "source-breaking … never a patch" in English and predates the marker. Negations (`non-breaking`) and `groundbreaking` are excluded, both taken from real fragments; `<!-- breaking: false -->` is the opt-out and always wins. Category-independent on purpose — a `Removed` public symbol is as breaking as a `Changed` one. Previous version comes from `CHANGELOG.md`, skipping a section that names the target, so it works on BOTH sides of the release bump. Exit 1 = refused, 2 = malformed fragment (bad marker value, unterminated comment) — never a silent pass. **No override flag**: the remedy is to tag the next minor. Wired in three places (`collate-changelog.sh`, `release-fast.yml` right after version validation, `release-checklist.sh` §6). The prose heuristic ignores code spans and folds newlines first, so a backticked `breaking` and a bullet wrapped between `non-` and `breaking` are both inert. A marker value is captured as everything up to `-->`, not as one token, so `<!-- breaking: not sure -->` and `<!-- breaking: -->` are *malformed* (exit 2) rather than "not a marker" — a token-shaped regex made a typo fail to match, get stripped as an ordinary comment, and ship unflagged. Both halves of the prose heuristic are bounded on purpose: code spans are matched as a RUN of backticks (a ``breaking`` written with two would otherwise stay visible) and the negation alternation is left-bounded (unbounded, "piano breaking" reads as "no breaking" and a real declaration passes). The marker is recognised in ANY comment span on a line, not only on a line that is nothing else — anchored to the whole line, a marker trailing a bullet fell through to the stripper and was deleted before the prose heuristic could see it, so a misplaced marker declared nothing at all. Detection runs on a code-span-stripped copy of the line, so a doc fragment quoting the marker in backticks stays inert. Self-tested by `test-check-breaking-change-bump.sh` (32 assertions) with a mutation test per direction |
| `lib/changelog-fragment.sh` | Sourced fragment-parsing primitives shared by the collator and the breaking guard (`frag_strip_comments_line`, `frag_is_category_tag_line`, `frag_drop_code_spans`, `frag_is_breaking_marker_line`, `frag_prose_claims_breaking`). The stripper writes to a global rather than echoing: `x="$(f "$line")"` runs in a subshell and would drop the multi-line comment state on every line, silently restoring the verbatim-copy bug |

Self-tested by `test-store-preflight.sh` (in `repo-hygiene`) |

It had no test seam: exercising it meant dispatching the workflow, which archives, signs and uploads a real TestFlight build — so every fix to it was validated in production, on a release, after it broke one (#2731, #2885, #2893). The test reads the real program (never a copy, so it cannot drift) and asserts FIRST that `app-store.yml` still invokes it — the drift hole extraction opened, since a renamed or dropped step would otherwise leave the suite green over nothing. Runs in `ci.yml` → `repo-hygiene` |

SKIPs honestly without creds. Self-tested by `test-store-sync.sh` (repo-hygiene) |
| `store-sync/asc_listing.py` | App Store listing drift diff + screenshot upload (#2612 P2). `--dry-run` (default, read-only) diffs live ASC text fields + screenshot `sourceFileChecksum` against `samples/ios-demo/distribution/app-store/` + `appstore-screenshots/`; `--apply-screenshots` uploads the repo screenshots (reserve → chunked PUT → commit `uploaded:true` + MD5) to the **editable** version, replacing each display-type set (delete-then-upload; a failed delete is fatal *before* any upload, so a half-replaced set can't happen). Live order is *expected* to follow repo filename order — Apple does not promise creation order, so the script PROBES it after upload and warns instead of asserting. Never creates a version — SKIPs honestly when none is editable. Listing TEXT stays owned by `app-store.yml`'s submit step. TWO CI callers since #2899: (1) `app-store.yml`'s submit step calls `apply_screenshots()` **inline**, between the listing-text sync and the review submission — the only moment an editable version exists, since that step creates it and Apple locks the metadata on submission; every release goes through this path, and it is deliberately never fatal (`except BaseException` — the function signals failures with `SystemExit`) so a screenshot cannot stop a release reaching App Review; (2) `app-store-screenshots.yml` (ubuntu, dispatch-only, no Xcode) remains for out-of-band refreshes, and can only write when a version happens to be open. Flag abbreviations are disabled on both store-sync scripts: `--apply` must not resolve into an upload. Same ASC env aliases as `store-preflight.sh`. **`--dry-run` is also the daily read-only `maintenance.yml` `asc-listing-drift` job** (#2612 P2 Phase C step 0, sibling of `store-preflight`) — the first CI caller of the ASC read-only path. It prints a `sourceFileChecksum` **provenance verdict** (`confirmed`/`unattested-match`/`md5-shaped`/`absent`/`other`/…): the MD5 keying the screenshot diff rests on is *measured, not assumed* (true by construction for anything this script uploaded — Apple echoes what we declare — so only console-sourced live sets are an honest sample). A repo-MD5 match therefore reports `unattested-match`, **not** `confirmed`, unless the operator attests provenance with `--screenshots-are-console-sourced` (which covers the draft too, and names its own source in the log so an inherited env var can't attest invisibly); without that gate a single `app-store-screenshots.yml` dispatch would have made the verdict permanently green on a tautology (caught in PR #2811 review). The probe also samples the **editable draft**'s screenshot sets and stamps every set with the version it was read from (`APP_IPHONE_67 @4.23.0`, `… @draft 4.24.0`), because a console upload lands on the draft — and that draft keeps its screenshots when it ships, so a set being live proves nothing about who uploaded it. Phase C's drift gate is now **wired on both surfaces, advisory**: §17 of `release-checklist.sh` WARNs at release time (NOT gated on a `confirmed` verdict — an advisory WARN is not the blocking bar, PR #2880), and the daily `maintenance.yml` `listing-drift` / `asc-listing-drift` jobs run the diff with `--fail-on-drift` and open a de-duplicated per-store tracking issue **only on a measured drift** (exit 3 — never on a credential-less skip or a mid-read crash), refreshed daily while the drift persists — and **auto-closed once the diff comes back clean** (#2835), through the shared `close-maintenance-issue.sh`. The close is gated on a *positive* measured-and-clear signal (`clean=1`: exit 0 **and** a non-empty log **and** no `[skip]` line), never on the bare exit 0, because 0 also covers the credential-less skip and a run where the tool never spoke — closing on that would silently retract a live finding the first time a secret expired. #2612 Phase C. Neither fails CI; promotion to blocking waits on n=5 |
| `close-maintenance-issue.sh` | Closes an auto-filed `maintenance.yml` tracking issue once its condition clears (#2835). Called by all five auto-filers (`skill-drift`, `deeplink-health`, `mcp-npm-freshness`, `listing-drift`, `asc-listing-drift`), which were one-directional before it — they opened and refreshed issues daily and never closed one, so #2835 stayed open 13 days after the npm lag it described was gone. Each caller passes its own **positive** measured-and-clear signal (`clean` / `resolved`), never the inverse of the open signal: for both store jobs exit 0 also means "credentials absent", and a failed `npm view` yields the same "no lag" as a genuine match. The lookup only ever matches an issue that is open, filed by `app/github-actions`, labelled `maintenance`, and title-matched — a human-filed issue can never be closed by it. `--dry-run` reports the target without touching it |
| `lib/android-cli.sh` | Shared helpers for Google's `android` CLI (screenshot, layout, install+launch) with `adb` fallback |
| `lib/as-count.sh` | `as_count` / `as_count_or_unknown` — the one place that turns `grep -c` output into a number safe to compare. `grep -c` prints its count **and exits 1** on no match, so the idiomatic `$(grep -c … \|\| echo 0)` yields the two-line value `0\n0`, `[ "$X" -eq 0 ]` dies with "integer expression expected", and under `set -e` the caller dies with it — a check that could never pass once anything was modified. Callers pass `\|\| true` and let the helper take the first line and default an empty value. ⚠️ `${1-}` FIRST, then the pattern strip: under `set -u` a combined `${1%%…}` on an ABSENT positional is fatal on bash 5 (every GitHub runner) and silently `''` on the bash 3.2 that ships with macOS — the self-test therefore passed locally and failed in CI on its own "no argument" assertion. The guard strips whole-line comments before scanning, because the library *documents* the broken form and the first version flagged its own prose; removing that exclusion makes the guard fail on documentation, which is how a guard gets deleted |

| `lib/extract-gate-selftests.sh` | Lists the gate self-test commands a workflow job runs, as a **validated** allowlist — the derivation behind `pre-push-check.sh` leg 19, which then EXECUTES what it finds. Deriving beats copying (a copied list goes stale the first time `repo-hygiene` gains a self-test, the #2988 shape), but it means running strings scraped out of YAML, so the safety property is stated explicitly on the OUTPUT rather than left implicit in a scrape regex: every emitted line must match an anchored `<bash\|python3> <plain repo-relative path>`, and anything else is dropped **and printed** as `REJECT:` on stderr — a silent drop would read as "there was nothing to run". Comments are stripped before the scrape, `..`/absolute operands are refused, and an empty list is returned as-is for the caller to judge (leg 19 has a discovery floor for exactly that, #3050). Self-tested by `test-extract-gate-selftests.sh` against **hostile** workflow fixtures, never against the real `ci.yml` — a green run has to mean "the extractor is safe", not "today's `ci.yml` happens to be tame" |
| `lib/gradle-run.sh` | Sourced helper that runs a Gradle task while KEEPING its output, and classifies the failure before anything names it — THREE classes, not two: **host setup** (`gradle_setup_reason` / `gradle_setup_fix`), **environment** (`gradle_infra_reason`), real failure; plus `gradle_run`, `gradle_log_tail`, `roborazzi_fresh_diff_count`, and the two reporters the gates actually call, `gradle_report_failure` and `script_report_failure`. Exists because `./gradlew <task> --quiet 2>/dev/null` + "any non-zero exit ⇒ <one hard-coded diagnosis>" is a lie generator: measured 2026-08-06, `pre-push-check.sh` reported "Android screenshot regression detected" for a `Gradle build daemon disappeared unexpectedly` (daemon contention), reproduced identically on a pristine clone of `main` — and `2>/dev/null` had deleted the one line that said so. The pattern table is deliberately NARROW: too broad and a genuine compile break gets waved through as "infrastructure", which is the same lie pointing the other way. ⚠️ Never re-add a bare `Could not resolve all …` row — Gradle prints that same line for an unreachable repository AND for a coordinate that does not exist (a code defect); only the transport rows discriminate, and that row is what let a release blocker degrade to a pass in review. `gradle_log_tail`'s trailing `|| true` is load-bearing too, not decoration: `grep -v` exits 1 on an all-boilerplate log, and under `set -euo pipefail` errexit kills the caller AT THE PIPELINE, so a `return 0` at the end of the function never runs. `roborazzi_fresh_diff_count` is the positive-proof half — a verdict on the goldens requires a comparison report NEWER than a marker taken before the run, because the goldens are not declared inputs of any task and a re-run comes back `UP-TO-DATE` having compared nothing. The host-setup class was added by #3065 and is checked FIRST: a fresh worktree has no `local.properties` (gitignored), so every Gradle step died with `SDK location not found` while `pre-push-check.sh` announced "public-API surface drifted" and prescribed `apiDump` — a remedy that commits a bogus `.api` diff. Like an infra failure it means the code was never judged; unlike it, re-running changes nothing, so the row carries the exact FIX (`sdk.dir=` / `ANDROID_HOME`, missing SDK package or licence, missing platform / build-tools / NDK, unusable JDK) and the caller must print it. `gradle_report_failure` reports four outcomes in order — host setup → environment → "died before it compared anything" → real failure — and takes an optional POSITIVE proof cue: apiCheck passes the two strings the Kotlin binary-compatibility validator actually prints (read out of its jar, not guessed), so a build that dies inside `apiBuild` reads as "not compared", never as a drift. That case is real — a poisoned instrumented-transform cache produced exactly it, and the first version of the #3065 fix still called it a drift. `script_report_failure` applies the same rule to every NON-Gradle checker leg of `pre-push-check.sh` (legs 9-13 and 15-18, 20 — do not re-pin that list to a range, #3103 renumbered it once already): exit >= 2 (or 126/127) is "could not run", a missing cue is "exited without reaching its verdict", and only a checker that printed its own finding gets the finding's name — and a cue must cover EVERY finding path of its checker, including early exits that never reach the tally (step 12). Anything that could not run is counted separately from a failure and still blocks: a gate that did not run is not a gate that passed. Used by `pre-push-check.sh` and `release-checklist.sh`; self-tested by `test-gradle-run.sh` |
| `test-gradle-run.sh` | Hermetic self-test for `lib/gradle-run.sh` (in `repo-hygiene`). Synthetic Gradle logs, no Gradle, no network. Asserts BOTH directions — the daemon/lock/OOM/network/disk fixtures classify as infra, and the compile-break and test-failure fixtures must NOT — plus the four measured Roborazzi report states (fresh clean / fresh with diffs / stale / corrupt), where a stale report must degrade to `unknown` and never to a silent `0`. Since #3065 it also drives the reporters on logs copied from real runs — the `SDK location not found` log, a genuine `.api` drift, a dead `apiBuild` — with the exact arguments step 14 passes, and reads what they PRINT and what they COUNT (a setup failure must never say "drifted", must warn against `apiDump` instead of prescribing it, and must land in the INCOMPLETE bucket). It also reads step 12's proof cue out of `pre-push-check.sh` and requires it to match both of that checker's finding paths. Mutation-tested three ways: with the daemon row deleted from the infra table, with the `SDK location not found` row deleted from the setup table, and with a proof cue that matches anything, the suite has to fail — otherwise its assertions are hollow. It already earned itself once — it caught that `|` could not be the table separator, since it is also the regex alternation operator |
| `lib/log-dir.sh` | Resolves the scratch directory `pre-push-check.sh` writes its logs to, PER WORKTREE (`pre_push_log_dir` / `pre_push_log_dir_create`). | `test-pre-push-log-dir.sh` | Hermetic self-test for `lib/log-dir.sh` (in `repo-hygiene`) — pure bash, no network, sub-second. That bidirectionality is the point: an unindexed skill is a file no session will think to open, strictly worse than the inline text it replaced. Mutation-tested — including on the trap that a file-wide `grep` for the skill name passes after its index row is deleted, because the name also appears in the hard-rules pointers |
| `cleanup-branches-worktrees.sh` | One-shot GC for stale `claude/*` branches **and** worktrees: deletes merged local + remote branches (single `git push --delete`, no bot-burst) and delegates worktree pruning to `worktree-auto-prune.sh`. Defaults to dry-run; `--yes` to act, `--keep <branch\|path>`, `--no-worktrees`. Current-branch / unmerged / open-PR guarded. Runs daily in `maintenance.yml` |

### CI Gate scripts (.github/scripts/)

A separate directory on purpose: `ci-gate.yml` is the ONE check branch
protection requires, and everything it calls has to exist in a plain
`actions/checkout` with no `.claude/` tooling around it. The gate's poll loop
stays inline in the workflow — the file it judges must not be one a PR can
rewrite — so each script here is a piece of that loop lifted out to be testable,
and every one of them is exercised by a suite in `ci.yml` → `repo-hygiene`.

| Script | Purpose |
|---|---|
| `ci-gate-qualify-runs.sh` | Attributes each check run to the WORKFLOW FILE that produced it, then collapses to one run per `[workflow, name]`. #2492 collapsed per NAME across the whole SHA, so a same-named run from another workflow with a higher `id` and `conclusion: success` displaced a real `failure` and the gate passed green over it (#3033). The map comes from `/actions/runs?head_sha=`, which publishes `check_suite_id → path`; a run whose suite is not in it (a non-Actions app) degrades to `app:<id>`, which is the pre-#3033 behaviour for that run and no worse. ⚠️ Do NOT "simplify" this to a collapse on `check_suite_id`: `cancel-in-progress` creates a NEW suite for the same workflow, which is exactly the duplicate #2492 exists to remove. Also carries the hostile-name normalisation (#3023) and drops the gate's own check and `Device QA — *`. Self-tested by `test-ci-gate-observations.sh` |
| `ci-gate-merge-observations.sh` | The sticky observation ledger (#3018). A check name seen once for this SHA is never un-seen: while GitHub builds a re-run attempt an entire suite can vanish from one Checks API read and return in the next, and on #3015 that window landed on the final poll — the gate aggregated ONE check run and passed. A name missing from a later read is kept as `status: vanished`, which the pending selector treats as not-completed, so the gate WAITS rather than concluding. Keyed on `[workflow, name]`, same pair as the qualifier. ⚠️ The live API is authoritative for a name it still reports, with one exception that is the whole point: a recorded `completed` is not overwritten by a later `queued` for the same name. Self-tested by `test-ci-gate-observations.sh` |
| `ci-gate-aggregate.sh` | Turns the merged observation set into the gate's verdict — required vs advisory (#1984/#2013), `Device QA` exclusion (#1588), `action_required` as pending rather than failure (#1543). Self-tested by `test-ci-gate-aggregation.sh` |
| `test-ci-gate-loop.sh` | The only suite that tests the gate's own POLL LOOP rather than the helpers it calls. It extracts the `run:` block from `ci-gate.yml` **by step name** with PyYAML and executes those bytes with `gh`, `sleep` and `date` stubbed against scripted Checks API reads. It exists because the #3018 suites stayed 21/21 green with the fix's own wiring deleted from the workflow — a self-declared gate passing with its own subject removed (#3047). ⚠️ A missing step name is a hard failure, never a skip, or a rename empties the suite silently. Every scenario is proven by mutation, and the assertions name the SITE they cover: an early `grep -qE '^ +- -n'` passed on a mutant because the other of the two blocks it could match was untouched |

### Quality gates (must pass before any push to main)

1. All versions aligned (run `sync-versions.sh`)
2. No lint errors in library modules
3. Unit tests pass (`./gradlew :sceneview-core:allTests`)
4. MCP tests pass (`cd mcp && npm test`)
5. llms.txt matches current public API
6. `STATE.md` reflects the work just done (CLAUDE.md holds stable facts only — putting session state there contradicts its own first rule)
7. No model-viewer or Three.js in website code
8. No external CDN dependencies in website
9. Public-API ABI matches the committed `.api` dumps (`./gradlew apiCheck` — intentional changes re-run `apiDump` and commit the diff)

`pre-push-check.sh` runs 20 legs covering these plus every cheap, deterministic,
offline step of `ci.yml`'s blocking jobs (demo-id parity, CREDITS drift, the
`android run` content gate, workflow shell blocks, the repo-hygiene gate
self-tests, and `quality-gate.sh --quick`). What it deliberately does NOT run —
and why each one is out — is the `CI-PARITY LEGS` comment block at the top of
that script (#3103). A CI check named in neither the legs nor that block is an
unaudited gap, not a decision.
